# 후속 작업 — 분석 결과에 따른 제안, 구현 미착수
- [ ] P0 파일 선택: TorrentEngine이 영상 확장자를 우선 필터링하도록 하고 영상이 없는 경우 오류 처리 정책을 정한다. 큰 비영상+작은 영상, 다중 영상, 영상 없음, 크기 0 테스트를 추가한다. 기존 앱 구조를 보존한다.
- [ ] P0 부분 다운로드 재생: 현재 VLC 직접 파일 읽기와 piece 검증 사이의 공백을 해결할 경로를 선정한다. 첫/끝 piece 또는 3% 대신 필요한 연속 구간과 컨테이너 인덱스 준비를 확인하고, 미완료 구간에서 재버퍼링·오류 복구가 가능한지 검증한다. 부족한 피어·일시 정지·다운로드 완료 전 탐색 시나리오를 포함한다.
- [ ] P0 취소/재시작: 엔진 작업 수명·취소 토큰 또는 세대 식별·콜백 유효성을 관리하고 세션 필드 동기화를 점검한다. 메타데이터 수신 전 취소, 빠른 재시작, 종료 직후 이전 콜백을 테스트하며 stop 시 선택 파일·통계 초기화 정책을 정한다.
- [ ] P0 입력/경로 보안: magnet 스킴·xt/infohash·길이·비정상 인코딩을 검증하고, 토렌트 파일 경로의 canonical path가 캐시 루트 안인지 검증한다. 링크 원문을 로그·일반 파일에 남기지 않는지 점검한다. 향후 링크 영속 저장이 필요하면 Android 보안 저장소를 사용하며 불필요한 원문 UI 상태 보관도 검토한다.
- [ ] P1 테스트: 기존 상태 생성 테스트에 더해 입력 파싱, 파일 선택, piece 경계·준비 판단, 상태 전환, 취소, 오류 복구의 의미 있는 단위 테스트를 설계한다. 통제된 합법적 테스트 토렌트로 magnet→metadata→download→buffer→play→seek→stop 통합 테스트를 추가한다. 현재 기기 테스트는 패키지명만 검증한다.
- [ ] P1 플레이어/수명주기: VLC EncounteredError·EndReached 처리, 재시도, 시스템 뒤로가기, 회전·백그라운드 전환 정책을 보강한다. 시간 비례 바이트 탐색의 부정확성 및 native 세션/플레이어 해제·JNI ABI별 동작을 실제 기기에서 검증한다. 캐시 사용량 상한·정리·다운로드 재개 정책을 정한다.
- [ ] P1 미사용 경로 정리 판단: ExoPlayer/DataSource와 HTTP 서버를 계속 유지할지 결정한다. 유지 시 DataSource의 piece 경계 전체 검증, open 시간 초과·중단·EOF 구분과 HTTP Range의 suffix/음수/역방향/다중 요청·416 응답을 테스트한다. HTTP 읽기도 파일 길이 대신 검증된 piece를 사용하도록 검토한다. 결정 전 삭제나 재작성은 하지 않는다.
- [ ] P2 빌드/설정: JAVA_HOME 또는 IDE Gradle JDK와 daemon JVM 25 설정을 개발 환경 문서에 명확히 한다. Debug 빌드·테스트 성공을 기준선으로 삼고 별도 clean/release/lint와 신규 환경 의존성 재현성을 확인한다. 미사용 libtorrent 버전 항목, JitPack 필요성, 두 플레이어·4 ABI 포함에 따른 APK 크기, EAP VLC 사용, release 최적화 정책을 검토한다. cleartext는 사용 경로에 맞게 제한하고 백업 대상도 확인한다.
- [ ] 작업 규칙: 현재는 분석 문서만 작성했으며 개발은 사용자 후속 지시 뒤 시작한다. 기존 Git 변경을 보존하고 코드 변경은 단일 파일·최대 10줄 및 관련 단위 테스트 원칙을 따른다. 테스트 디렉터리 수정이 필요한 경우 `app/src/main/java` 한정 규칙과 충돌하는 범위를 구현 전에 명확히 한다. 새 외부 라이브러리는 승인 없이 추가하지 않는다.
