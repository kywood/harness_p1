# 출시 첫 주 지표 체크리스트 (대한민국 단독 출시)

- 작성: 2026-11-12, marketing (#115)
- 대상: v.2026.11.12.003(versionCode 28), 대한민국 프로덕션
- marketing은 Play Console·AdMob에 로그인하지 않는다. 사용자가 아래 화면을 캡처하거나 CSV로 내보내 주면 `marketing/reports/<YYYY-MM-DD>.md`로 정리한다.
- 메뉴 이름은 Console 화면 개편에 따라 바뀔 수 있다. 아래 경로는 2026-11-12 기준 Google 도움말과 일반적인 Console 구성으로 적었고, 실제 화면과 다르면 사용자가 알려 주면 고친다(경로 일부 미확인).

## 1. 언제 볼까

| 시점 | 볼 것 | 이유 |
|---|---|---|
| 출시 당일(D0) 저녁 | 출시 상태, 비정상 종료 첫 보고, AdMob 노출 0이 아닌지 | 릴리스 빌드 실기기 광고 확인을 출시 전에 못 했다(출시 전 점검 5번) |
| D1 | 설치·제거, 비정상 종료·ANR, 첫 리뷰 | 큰 문제는 첫날 드러난다 |
| D3 | 같은 항목 + 평점 추이, eCPM | 단계적 출시 비율을 올릴지 판단 |
| D7 | 주간 정리 → 첫 보고서 | 다음 주 우선순위(PM) |

Play Console 통계는 하루 이상 늦게 반영될 수 있고, Android vitals는 표본이 적으면 값이 비어 있을 수 있다(첫 주 설치가 적으면 정상).

## 2. 지표별 위치와 기준

### 2.1 Play Console

| 지표 | 위치 (Play Console > PiecePlay) | 첫 주에 볼 값 | 경고 신호 |
|---|---|---|---|
| 설치(신규 사용자 획득) | 대시보드, 또는 통계 / 사용자 획득 > 획득 보고서 | 일별 신규 설치 기기·사용자, 국가(대한민국) | 설치 0이 이틀 이상 → 등록정보 노출 문제 의심 |
| 제거 | 통계 > 측정항목에서 "기기 제거"·"사용자 손실" 선택 | 일별 제거 수, 설치 대비 제거 비율 | 같은 날 설치 대비 제거가 절반 이상 |
| 스토어 등록정보 방문·전환 | 사용자 획득 > 획득 보고서(스토어 등록정보 방문자 → 설치) | 방문자 수, 전환율, 유입 경로(Play 검색/둘러보기/외부) | 방문은 있는데 전환율이 낮음 → 아이콘·스크린샷·간단한 설명 문제 |
| 검색어 | 획득 보고서의 검색어(검색 유입) 표 | 어떤 검색어로 들어왔나 | 기대 키워드("토렌트 플레이어" 등)가 없음 → ASO 재검토 |
| 평점 | 품질 > 평점 및 리뷰 > 평점 | 일별 평균, 누적 평점, 별점 분포 | 1~2점 비중이 높음 |
| 리뷰 | 품질 > 평점 및 리뷰 > 리뷰 | 리뷰 본문, 기기·Android 버전, 앱 버전 | 같은 문제를 말하는 리뷰가 2개 이상 |
| 비정상 종료율 | 품질 > Android vitals > 개요 / 비정상 종료 및 ANR | **사용자 인식 비정상 종료율** | 전체 **1.09%** 이상 또는 특정 휴대전화 모델 **8%** 이상(Google 비정상 동작 기준) |
| ANR 비율 | 같은 화면 | **사용자 인식 ANR 비율** | 전체 **0.47%** 이상 또는 특정 모델 **8%** 이상 |
| 배터리·wake lock | Android vitals > 개요 | 과도한 부분 wake lock | 불필요한 부분 wake lock **5%** 이상(기준). 라이브러리(WorkManager·광고 SDK)가 WAKE_LOCK을 쓴다 |
| 사전 출시 보고서 | 테스트 > 사전 출시 보고서 | 비정상 종료, 접근성·보안 경고 | 프로덕션 출시 전 자동 테스트에서 비정상 종료 |

기준 출처: [Android vitals 비정상적인 동작 기준](https://developer.android.com/topic/performance/vitals) (2026-11-12 확인). 같은 페이지에 "메모리 사용량, 비트맵 메모리, **코드 최적화** 기준을 넘는 앱은 **2027년 2월부터** 스토어 가시성에 영향"이 있다고 적혀 있다. 릴리스 빌드는 R8 최적화가 꺼져 있다(루트 `CLAUDE.md`) → PM 확인 필요 항목으로 넘긴다.

### 2.2 AdMob

| 지표 | 위치 (AdMob > 앱 PiecePlay) | 첫 주에 볼 값 | 경고 신호 |
|---|---|---|---|
| 요청·일치율 | 보고서(앱별·광고 단위별) | 광고 요청, 일치된 요청, 일치율 | 요청은 있는데 일치율이 매우 낮음 → 새 앱 계정 제한·정책 확인 |
| 노출 | 홈 / 보고서 | 배너·전면 노출 수 | 출시 후 하루 넘게 노출 0 → 릴리스 광고 단위·UMP 동의 흐름 점검 |
| 노출률(표시율) | 보고서 측정항목 "표시율" | 전면 광고 로드 대비 표시 | 매우 낮음 → 전면 조건(5분/5회, 10분 간격)과 로드 시점 확인 |
| eCPM | 보고서 측정항목 "노출 eCPM" | 배너·전면 각각의 eCPM(원) | 값 자체보다 추이를 본다. 첫 주는 표본이 적어 흔들린다 |
| 예상 수입 | 홈 | 일별 예상 수입 | 참고만 |
| 정책 센터 | 정책 센터 | 정책 위반·광고 게재 제한 알림 | 알림이 하나라도 있으면 즉시 PM에 공유 |
| 개인정보 및 메시지 | 개인정보 및 메시지(UMP) | 동의 메시지 노출·동의율 | 한국은 GDPR 지역이 아니어서 메시지가 거의 안 뜨는 것이 정상일 수 있음(미확인) |

AdMob 측정항목 정의: [AdMob 보고서 측정항목](https://support.google.com/admob/answer/7356092) (링크만 확인, 본문 대조는 미확인).

## 3. 사용자에게 받을 자료

정리를 위해 아래 중 가능한 것을 주면 된다. **이메일·리뷰 작성자 이름·기기 고유 정보는 가리거나 빼고** 준다(가릴 수 없으면 `launch/private/`에 두고 경로만 알려 준다).

| # | 자료 | 형식 | 주기 |
|---|---|---|---|
| 1 | Play Console 대시보드 첫 화면 | 캡처 | D1, D3, D7 |
| 2 | 통계: 신규 사용자 획득·사용자 손실(기기 제거) 일별, 기간 출시일~오늘 | CSV 내보내기(통계 화면의 내보내기) 또는 캡처 | D7 |
| 3 | 획득 보고서: 스토어 등록정보 방문자·전환율·유입 경로·검색어 | 캡처 | D7 |
| 4 | 평점 및 리뷰: 평점 그래프 + 리뷰 목록 | 캡처 또는 리뷰 CSV(작성자 열 삭제) | D1, D3, D7 |
| 5 | Android vitals 개요: 비정상 종료율·ANR 비율 | 캡처 | D1, D3, D7 |
| 6 | 비정상 종료 및 ANR 상위 클러스터 1~3개의 스택 트레이스 | 텍스트 복사 | 문제가 있을 때 |
| 7 | AdMob 홈 + 보고서(앱 PiecePlay, 광고 단위별, 일별: 요청·일치율·노출·표시율·eCPM·예상 수입) | 보고서 CSV 내보내기 또는 캡처 | D1, D7 |
| 8 | AdMob 정책 센터 | 캡처 | 알림이 있을 때 |

Play Console 월별 보고서는 Google Cloud Storage 버킷으로도 내보낼 수 있지만(다운로드 보고서) 첫 주에는 화면 캡처로 충분하다.

## 4. D7 보고서 틀

`marketing/reports/<YYYY-MM-DD>.md`에 이 순서로 쓴다.

1. 요약 3줄
2. 설치·제거·순증(일별 표), 유입 경로, 검색어
3. 평점·리뷰: 평균, 분포, 리뷰 주제별 분류(버그/기능 요청/광고/기타), 답변 문안은 `marketing/reviews/`
4. 품질: 비정상 종료율·ANR 비율과 기준 대비, 상위 문제
5. 광고: 노출, 표시율, eCPM, 예상 수입
6. 제안과 PM 결정 필요 항목
