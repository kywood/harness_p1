### 2.1 GeekNews Show

- **위치**: [news.hada.io/show](https://news.hada.io/show) → 글쓰기에서 **Show** 선택. 링크는 **Play 스토어 주소**(블로그·YouTube 링크는 Show 규칙상 안 된다).
- **시점**: 블로그 글이 올라간 뒤 평일 오전. 새 계정이면 글쓰기 대기 기간이 있으니 미리 가입해 둔다. 같은 프로젝트는 재등록 제한이 있어 **한 번만** 올린다(재등록 가능 기간은 미확인).
- **주의**: 댓글에서 저작권 질문이 나오면 방어하지 말고 사실만 답한다(아래 답변 예시). 사이트 이름을 언급하는 댓글에는 반응하지 않는다.

제목:

```
Show GN: PiecePlay – 마그넷 링크를 받으면서 바로 재생하는 안드로이드 플레이어
```

본문:

```
안드로이드 앱 PiecePlay를 혼자 만들어 출시한 개발자입니다. 직접 만든 앱을 소개합니다.

마그넷 링크나 .torrent 파일 주소를 넣으면 다 받기 전에 재생을 시작합니다.

- 재생 위치 바로 앞 조각부터 먼저 받고, 다른 위치로 이동하면 그 위치부터 다시 받습니다.
- 조각 맵으로 받은 부분과 본 부분을 보여 줍니다.
- 다른 사용자에게 업로드하지 않고, 다 받으면 공유를 멈춥니다.
- 재생·준비 중에는 광고가 나오지 않습니다(배너는 메인·재생 목록에만).
- 재생 목록과 이어보기 위치는 기기 안에 암호화해 둡니다. 회원가입이 없습니다.

기술: libtorrent + LibVLC. 앱 안 로컬 HTTP 서버가 Range 요청마다 해당 조각의 해시 검증이 끝날 때까지 기다렸다가 플레이어에 넘깁니다.
지금은 한국 Play 스토어에만 있고 화면은 한국어입니다. 자막과 브라우저 마그넷 링크로 바로 열기를 다음 업데이트로 준비하고 있어 의견을 듣고 싶습니다.

스크린샷·영상 속 영상은 Blender Foundation 오픈 무비(CC BY)입니다. 권리를 가진 콘텐츠만 재생해 주세요.

### 2.2 클리앙 개발한당

- **위치**: [클리앙 개발한당](https://www.clien.net/service/board/cm_app) (로그인·이메일 인증 필요). 유료 "직접홍보" 게시판은 쓰지 않는다.
- **형식**: **개발 경험 공유가 본문**이어야 한다(공지: 홍보만을 위한 글은 삭제). 앱 링크는 마지막에 하나. 광고가 들어 있는 무료 앱이라는 사실을 숨기지 않는다.
- **시점**: 블로그 글 다음, GeekNews와 다른 날. 게시 전 공지와 "개발한당 행동강령 v1.0"을 사용자가 직접 읽는다(미확인).
- **주의**: 삭제되면 다시 올리지 않는다. 같은 내용을 다른 클리앙 게시판에 올리지 않는다.

제목:

```
[개발기] 받으면서 바로 재생하는 토렌트 플레이어를 만들며 배운 것 (직접 만든 앱)
```

본문:

```
안녕하세요. 혼자 안드로이드 앱을 만들어 출시한 회원입니다. 직접 만든 앱 이야기라 미리 밝혀 둡니다.

다 받을 때까지 기다리지 않고 재생하는 플레이어를 만들면서 부딪힌 문제 세 가지를 나눕니다.

1) 순서대로 받으면 중간으로 이동할 때 막힌다
처음엔 앞에서부터 차례로 받았는데, 중간으로 이동하면 그 위치가 올 때까지 기다려야 했습니다. 지금은 재생 위치 바로 앞 구간에 마감 시간을 걸어 그 조각부터 받고, 이동하면 그 창을 옮깁니다.

2) 아직 안 받은 부분을 플레이어가 읽으려 할 때
앱 안에 작은 HTTP 서버를 두고, 플레이어의 Range 요청이 오면 그 조각의 해시 검증이 끝날 때까지 기다렸다가 넘깁니다. 검증 전 데이터는 넘기지 않습니다.

3) 업로드를 하지 않기로 한 이유
모바일 데이터를 쓰는 휴대폰에서 다른 사람에게 올려 보내는 것이 부담스러워, 업로드 없이 받고 다 받으면 공유를 멈추게 했습니다.

## 3. 채널 운영 공통 주의점

- **한 채널에 한 번, 날짜를 나눠서.** 같은 문장을 복사해 여러 곳에 동시에 올리면 도배·바이럴로 보인다.
- **계정 하나로, 본인으로.** 다른 계정으로 칭찬 댓글을 달거나 추천을 누르지 않는다(클리앙 규칙 "일반적인 회원으로 가장하여 홍보성 게시물" 금지).
- **댓글 대응은 24시간 안에, 사실만.** 저작권 논쟁에 끌려가지 않는다. 사이트·작품 이름이 나오는 댓글에는 반응하지 않는다.
- **삭제되면 다시 올리지 않는다.** 이유를 묻고, 규칙에 맞게 고칠 수 있을 때만 운영자 안내에 따라 다시 올린다.

### 4.4 테스터·지인에게 리뷰를 요청할 때 (정책)

[평점·리뷰·설치 정책](https://support.google.com/googleplay/android-developer/answer/9898684) 기준:

- **된다**: 대가 없이 "써 보고 솔직한 리뷰를 남겨 달라"고 부탁하기. 명확하고 속이지 않는 방식으로 평점을 요청하기.
- **안 된다**: 보상(쿠폰·상품·돈·기프티콘)을 걸고 리뷰·평점 요청, 별 5개를 써 달라고 하기, 같은 사람이 여러 계정으로 쓰기, 사용자인 척 평점을 반복 제출하기, 설치·평점을 늘리는 자동화 서비스, 강제하거나 속이는 팝업.
- 테스터 연락처는 `launch/private/`에만 둔다. 이 문서와 커밋에 옮기지 않는다.
- 요청 문안:

```
PiecePlay를 출시했습니다. 시간 되실 때 써 보시고, 좋았던 점이나 불편했던 점을 Play 스토어 리뷰로 솔직하게 남겨 주시면 개선에 큰 도움이 됩니다. (리뷰는 선택이고, 별점은 느끼신 대로 주시면 됩니다.)
```

- 앱 안 리뷰 요청(In-App Review API)은 코드 변경이라 이번 범위 밖이다. 나중에 넣는다면 충분히 써 본 뒤에, 질문 없이, 버튼으로 띄우지 않고, 카드를 꾸미거나 지우지 않는 규칙을 지킨다([In-App Review 가이드](https://developer.android.com/guide/playcore/in-app-review)). 필요하면 `planning/requests/` 형식으로 제안한다.
