## 순위 근거 요약

- 1·2는 출시 심사와 첫 사용 실패율에 직접 걸린다. 토렌트 앱은 첫 시도가 120초 타임아웃으로 끝나기 쉬운데, 지금은 다시 시도 수단이 없다.
- 3은 작업이 작은데 재방문 경로를 크게 줄인다(복사·전환·붙여넣기 → 탭 한 번).
- 4·5는 기대치 관리와 1점 리뷰 예방. 5의 확인 창만 먼저 하고 설정 화면은 나중에 해도 된다.
- 6은 사용자 가치가 크지만 2단계가 엔진 파일 선택 규칙을 바꾸므로 출시 후로 둔다.
- 9는 가치가 크지만 권한·Play 신고가 늘어 출시 직전에 넣으면 심사 위험이 커진다.

## 겹치는 작업

- 2와 13: 코드 안 한국어 문구를 리소스로 옮기는 일이 겹친다. 2를 먼저 하면 13이 작아진다.
- 1과 4: 이용 안내 문장을 같이 쓴다.
- 5와 9: 설정 화면·연결 감시를 함께 쓴다. 5의 설정 화면이 생기면 9·12·16의 설정도 그곳에 둔다.
- 3과 1: 링크 열기로 기능이 더 드러나므로 이용 안내를 함께 내는 편이 안전하다.

## 결정 필요

1. 출시 전 범위: 1·2만 넣을지, 3·4·5(확인 창)까지 넣을지
2. 개인정보처리방침 호스팅 위치와 연락 이메일(launch, 개인정보는 `launch/private/` 기준)
3. 첫 사용 안내에 샘플(공개 라이선스) 마그넷을 넣을지
4. `.torrent` 로컬 파일 열기를 링크 열기(3)에 포함할지
5. 자막 1단계만 먼저 할지, 토렌트 안 자막 파일 받기(2단계)까지 할지
6. 재생 목록 50개를 넘어 빠지는 항목의 파일을 함께 지울지(지금은 남는 것으로 보임)
7. 메인 이어보기 카드를 끌 수 있게 할지(사생활)
8. 백그라운드 다운로드를 출시 후 첫 업데이트에 넣을지, Android 15 `dataSync` 시간 제한 대안 검토 범위
9. 영어 지원 시 기본 언어를 영어로 바꿀지, 첫 출시 국가 범위
10. 인앱 리뷰 라이브러리(외부 의존성) 추가 승인
11. 새 용어 표 추가 요청: "설정", "Wi-Fi 대기", "이어보기 카드", "이용 안내"
12. 루트 `CLAUDE.md`의 "문자열은 Kotlin 코드에 하드코딩", "영상은 cacheDir" 설명이 현재 코드와 다르다 — 문서 갱신 배정 여부
