## 순위 근거 요약

- 1·2는 출시 심사와 첫 사용 실패율에 직접 걸린다. Play 지식재산권 정책은 "침해를 부추기는 설명·스크린샷"을 위반 예시로 들고, 토렌트 앱은 첫 시도가 120초 타임아웃으로 끝나기 쉬운데 지금은 다시 시도 수단이 없다.
- 3은 작업이 작은데 재방문 경로를 크게 줄인다(복사·전환·붙여넣기 → 탭 한 번). µTorrent·Flud는 브라우저 마그넷 링크를 인식한다.
- 4·5는 기대치 관리와 1점 리뷰 예방. 경쟁 범용 클라이언트는 모두 Wi-Fi 전용을 갖췄다.
- 6은 경쟁 스트리밍 앱(Amnis·TVS)과의 가장 큰 격차지만 2단계가 엔진 파일 선택 규칙을 바꾸므로 출시 후로 둔다.
- 9·14는 가치가 크지만 권한·외부 의존성·Play 신고가 늘어 출시 직전에는 넣지 않는다.
- 경쟁 앱 리뷰의 1순위 불만은 끼어드는 광고다. PiecePlay의 지금 광고 규칙(재생 중 없음)은 유지하는 것을 전제로 했다.

## 겹치는 작업

- 2와 13: 코드 안 한국어 문구를 리소스로 옮기는 일이 겹친다. 2를 먼저 하면 13이 작아진다.
- 1과 4: 이용 안내 문장을 같이 쓴다. 1과 3·17: 기능이 더 드러나므로 이용 안내를 먼저 내는 편이 안전하다.
- 5와 9: 설정 화면·연결 감시를 함께 쓴다. 5의 설정 화면이 생기면 9·12·16·19의 설정도 그곳에 둔다.
- 9와 14: 휴대폰 화면이 꺼진 동안 유지하는 구조(포그라운드 서비스)가 겹친다.

## 결정 필요

1. 출시 전 범위: 1·2만 넣을지, 3·4·5(확인 창)까지 넣을지(3·4·5는 새 기능이므로 사용자 승인 필요)
2. 개인정보처리방침 호스팅 위치와 연락 이메일(launch, 개인정보는 `launch/private/` 기준)
3. 첫 사용 안내에 샘플(공개 라이선스) 마그넷을 넣을지
4. `.torrent` 로컬 파일 열기를 링크 열기(3)에 포함할지
5. 자막 1단계만 먼저 할지, 토렌트 안 자막 파일 받기(2단계)까지 할지
6. 재생 목록 50개를 넘어 빠지는 항목의 파일을 함께 지울지(지금은 남는 것으로 보임)
7. 메인 이어보기 카드를 끌 수 있게 할지(사생활)
8. 백그라운드 다운로드를 출시 후 첫 업데이트에 넣을지, Android 15 `dataSync` 시간 제한 대안 검토 범위
9. 영어 지원 시 기본 언어를 영어로 바꿀지, 첫 출시 국가 범위
10. 외부 의존성 추가 승인: 인앱 리뷰(15), Play Billing(16), Cast SDK(14)
11. 수익 모델: 광고만 / 광고 + 제거 결제(16)
12. 내보내기(17)를 지식재산권 정책 위험을 감수하고 넣을지
13. 스토어 설명에 "재생 중 광고 없음", "업로드하지 않음"을 강점으로 쓸지, 스크린샷에 공개 라이선스 영상만 쓰는 규칙을 #49에 전달할지(launch)
14. 새 용어 표 추가 요청: "설정", "Wi-Fi 대기", "이어보기 카드", "이용 안내", "TV로 보내기", "광고 제거"
15. 루트 `CLAUDE.md`의 "문자열은 Kotlin 코드에 하드코딩", "영상은 cacheDir" 설명이 현재 코드와 다르다 — 문서 갱신 배정 여부
