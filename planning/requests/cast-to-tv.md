# 요구사항(새 기능 제안): TV로 보내기 (Chromecast)

출처: [market/analysis.md](../market/analysis.md) §8 — Amnis·TVS가 Chromecast를 내세운다.

## 1. 문제
휴대폰으로 받은 영화를 거실 TV로 보고 싶은 사용자가 할 방법이 없다. 화면 미러링(기기 기능)은 화질·지연이 나쁘고 휴대폰 화면을 계속 켜 둬야 한다. 경쟁 스트리밍 앱은 Chromecast를 기본으로 내세운다.

## 2. 원하는 동작
1. 같은 Wi-Fi에 Chromecast·Google TV가 있으면 재생 화면 상단에 "TV로 보내기" 아이콘이 보인다.
2. 누르고 기기를 고르면 TV에서 같은 위치부터 재생되고, 휴대폰은 리모컨 화면(재생/일시 정지, 10초 이동, 재생 막대, 받은 구간·조각 맵, 연결 끊기)으로 바뀐다.
3. 휴대폰은 계속 토렌트를 받으면서 TV에 영상을 보낸다. 휴대폰 화면이 꺼져도 이어진다.
4. 연결을 끊으면 휴대폰에서 같은 위치부터 이어서 재생한다. 이어보기 위치 저장은 TV 재생 중에도 동작한다.
5. TV가 지원하지 않는 형식이면 "이 영상 형식은 TV에서 바로 재생할 수 없습니다."를 보이고 휴대폰 재생을 유지한다.

## 3. 완료 조건
- 같은 Wi-Fi의 Chromecast에 mp4(H.264) 영상을 보내 재생·탐색·일시 정지가 된다.
- 받지 않은 구간으로 탐색하면 TV가 기다렸다가 재생한다(휴대폰 리모컨에 대기 안내).
- 연결을 끊으면 휴대폰이 마지막 TV 위치에서 이어 재생한다.
- 지원하지 않는 형식(예: 일부 mkv 코덱)에서 오류 문구가 보이고 앱이 멈추지 않는다.

## 4. 범위 밖
- 실시간 변환(트랜스코딩), DLNA·AirPlay, Android TV용 앱

## 5. 영향
- design: 상단 아이콘, 기기 선택, 리모컨 화면(M)
- program: Cast SDK 연결, 로컬 스트림 서버를 같은 네트워크에 공개(지금은 `127.0.0.1` 전용), 휴대폰 화면 꺼짐 중 유지(포그라운드 서비스 필요 가능성 → [background-download.md](background-download.md)와 겹침)(L)
- 정책·보안
  - **외부 의존성 추가**(Google Cast SDK) → 사용자 승인 필요.
  - 로컬 스트림을 LAN에 열면 같은 네트워크의 다른 기기가 접근할 수 있다. 접근 토큰 등 보호가 필요하고, 평문 통신 허용 범위(`network_security_config`, `NetworkSpec`)가 바뀐다.
  - 권한: 근처 기기 탐색에 따라 Android 13+ `NEARBY_WIFI_DEVICES` 등이 필요할 수 있다(program 확인).
  - 데이터 보안 신고: 수집 항목 변경 없을 것으로 보이나 Cast SDK 수집 항목 확인 필요.

## 결정 필요
- 도입 여부(외부 의존성·보안 범위가 큼). 도입한다면 백그라운드 다운로드 이후에.
