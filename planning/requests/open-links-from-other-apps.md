# 요구사항: 다른 앱의 마그넷·토렌트 링크로 PiecePlay 열기

## 1. 문제
브라우저·메신저에서 마그넷 링크를 누르거나 "공유"해도 PiecePlay가 선택지에 나오지 않는다. 사용자는 링크를 길게 눌러 복사 → 앱 전환 → 붙여넣기 → 바로 재생을 매번 해야 한다. 재방문(리텐션)을 가장 크게 좌우하는 진입 경로가 빠져 있다.

## 2. 원하는 동작
1. 다른 앱에서 `magnet:` 링크를 누르면 PiecePlay가 연결 앱 후보로 뜬다.
2. 다른 앱의 "공유"로 텍스트(마그넷 또는 http(s) `.torrent` 주소)를 보내면 PiecePlay가 공유 대상에 뜬다.
3. PiecePlay가 열리면 메인 입력란에 링크가 채워진 채로, 확인 시트가 뜬다: 링크 요약(이름 `dn` 있으면 이름) + "바로 재생" / "재생 목록에 받아 두기" / "취소".
4. 재생 중에 링크가 들어오면 재생을 끊지 않고 같은 확인 시트에서 "받아 두기"만 기본으로 권한다.
5. 기기 파일 관리자에서 `.torrent` 파일을 열면 같은 흐름으로 처리한다(파일 내용을 읽어 마그넷으로 변환).

## 3. 완료 조건
- 크롬에서 마그넷 링크를 누르면 PiecePlay가 후보로 뜨고, 고르면 확인 시트가 보인다.
- 메신저에서 마그넷 텍스트를 공유하면 PiecePlay로 보낼 수 있다.
- 확인 시트 없이 자동으로 재생·다운로드가 시작되지 않는다(사용자 확인 필수).
- 들어온 링크는 평문으로 로그에 남지 않는다.

## 4. 범위 밖
- `http(s)://…/*.torrent` URL 전체를 가로채는 웹 링크 필터(도메인을 특정할 수 없어 부적절)
- 앱 안 브라우저·검색

## 5. 영향
- design: 확인 시트(S)
- program: intent filter(`VIEW` magnet 스킴, `SEND` text/plain, `.torrent` 파일 `application/x-bittorrent`), 들어온 값 검증, 재생 중 처리(S~M)
- 정책: 권한 추가 없음. 데이터 수집 변경 없음. 다만 스토어 설명에 "토렌트 링크를 연다"는 기능이 더 분명해지므로 지식재산권 정책 대비 이용 안내([policy-notice-and-privacy.md](policy-notice-and-privacy.md))를 함께 넣기를 권한다.

## 결정 필요
- `.torrent` 로컬 파일 열기(5번)를 이번 범위에 넣을지
