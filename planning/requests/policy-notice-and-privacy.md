# 요구사항: 개인정보처리방침·이용 안내(합법 콘텐츠)·오픈소스 라이선스 진입점

구분: 개선·오류. 시안: `design/specs/main-legal-footer.md`(A), `design/specs/open-source-licenses.md`(B), `design/specs/usage-guide.md`(C). design 되묻기 답: `design/reviews/planning-60.md` 3-1(Q2·Q10~Q12).

## 1. 문제
- 앱에 AdMob·UMP SDK가 있어 광고 ID 등 기기 식별 정보가 수집된다. Google Play 사용자 데이터 정책은 개인정보처리방침을 스토어 등록정보와 **앱 안**에 둘 것을 요구한다. 지금 앱 안에 링크가 없고, `launch/`에도 개인정보처리방침 문서가 없다.
- 토렌트 클라이언트는 Play 지식재산권 정책 심사에서 "저작권 침해 조장" 여부를 본다. 앱 안에 "권리가 있는 콘텐츠만 재생하라"는 안내가 전혀 없다.
- LibVLC(LGPL) 등 오픈소스 구성요소의 라이선스 고지가 앱 안에 없다(launch 출시 전 점검에서 "수정 필요").
- 사용자도 앱이 무엇을 저장하고 무엇을 보내는지(업로드하지 않음, 기기 안 암호화) 알 곳이 없다. 이것은 이 앱의 장점인데 드러나지 않는다.

## 2. 원하는 동작
1. 메인 하단에 저작권 안내 한 줄과 링크 묶음이 있다(시안 A): "이용할 권리가 있는 콘텐츠만 재생하세요." / 이용 안내 · 개인정보처리방침 · 오픈소스 라이선스 · (동의 필요 지역) 광고 개인정보 설정 / 버전. 링크 묶음과 배너 광고 사이는 충분히 띄운다(잘못 누르기 방지). 설정 화면은 만들지 않는다.
2. "개인정보처리방침"은 웹 페이지(외부 브라우저)로 연다. 내용: 앱 자체는 서버로 데이터를 보내지 않음, 재생 목록·진행 정보는 기기 안에 암호화 저장, 광고 SDK가 수집하는 항목, 삭제 방법(앱 삭제·재생 목록 삭제), 연락처. URL은 앱 안 한 곳(리소스)에서 읽는다.
3. "이용 안내"는 **앱 안 하단 시트**로 연다(오프라인에서도 읽히고 심사관이 앱 안에서 바로 확인, Q2). 맨 위 강조 문장 "이용할 권리가 있는 콘텐츠만 재생하세요."(Q10 확정) + PiecePlay는 콘텐츠를 제공하거나 찾아 주지 않으며 책임이 사용자에게 있다는 설명, 앱이 하는 일(선택한 영상 하나만 받음, 업로드하지 않음, 완료 후 공유 중단), 저장 위치와 정리 방법. 시트 맨 위에 "사용 방법 다시 보기"(첫 사용 안내 다시 열기, [first-run-guide.md](first-run-guide.md))를 둔다.
   - 개인정보처리방침 웹 문서에도 "이용 안내" 절을 두고 앱 안 시트와 같은 저작권 문장을 쓴다. 앱 안 시트가 기준이다(launch 작성).
4. "오픈소스 라이선스"는 앱 안 화면으로 연다(시안 B, Q12): 구성요소 이름·라이선스 종류 목록, 누르면 전문. 전문은 실제 배포 산출물에 포함된 라이선스 파일과 일치해야 한다.
5. 첫 사용 안내 마지막 장에서도 같은 저작권 문장(같은 문자열)을 보여 준다.
6. 스토어 설명에도 같은 뜻의 문장을 넣는다(문구 통일 여부는 launch 판단).

## 3. 완료 조건
- 메인에서 두 번 이하의 탭으로 개인정보처리방침 URL이 열린다.
- 개인정보처리방침 URL이 Play Console 등록정보의 URL과 같다.
- 메인 하단에 "이용할 권리가 있는 콘텐츠만 재생하세요."가 늘 보인다(360dp 세로 화면에서 잘리지 않음).
- 이용 안내 시트가 오프라인에서도 열리고, 맨 위에 같은 저작권 문장이 있다.
- 오픈소스 라이선스 화면에 앱에 포함된 오픈소스 구성요소(최소 LibVLC, libtorrent4j, NanoHTTPD)와 라이선스 전문이 있다.
- 배너·전면 광고 노출 조건은 바뀌지 않는다. 이용 안내·라이선스 화면에는 광고가 없다.

## 4. 범위 밖
- 이용약관 동의 절차(체크박스 강제), 신고 기능, 콘텐츠 필터링
- 설정 화면(→ [mobile-data-guard.md](mobile-data-guard.md) 승인 시 함께)
- 개인정보처리방침 호스팅 방법 결정(launch·PM, 사용자 결정)

## 5. 영향
- design: 시안 A·B·C 완료. `AppBottomSheet` 공용 추출 포함(S~M)
- program: 메인 하단 콜백, 브라우저 열기, 이용 안내 시트 상태, `AppScreen`에 오픈소스 라이선스 화면 추가, 라이선스 전문 리소스(S~M)
- launch: 개인정보처리방침 문안(이용 안내 절 포함) 작성·호스팅, 데이터 보안 양식과 내용 일치 확인, 스토어 설명 저작권 문장
- 정책: **출시 심사 위험을 줄이는 변경**. 데이터 수집 항목은 바뀌지 않으므로 데이터 보안 신고 변경 없음. 외부 브라우저 열기는 권한 불필요. 오픈소스 고지는 LGPL 의무 이행.

## 결정 필요
- **개인정보처리방침 URL(호스팅 위치)과 연락 이메일 — 사용자 결정 대기(Q11).** 이메일은 개인정보이므로 `launch/private/` 기준. URL이 정해지기 전에는 구현 배정을 하지 않고, URL 없이 출시하지 않는다.
