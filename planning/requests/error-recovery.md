# 요구사항: 실패 시 복구 흐름과 오류 문구 정리

구분: 개선·오류. 문구·배치 시안: `design/specs/error-recovery.md`(시안 D). design 되묻기 답: `design/reviews/planning-60.md` 3-1(Q1·Q4~Q7·Q13).

## 1. 문제
- 토렌트 정보를 120초 동안 못 받으면 메인으로 돌아가 문구만 보인다. 링크를 다시 붙여넣어야 하는 것으로 보이고(미확인), "다시 시도" 수단이 없다.
- 준비 화면에서 기다리는 동안 경과 시간·기대치가 본문에 없다. 피어가 0명이어도 사용자는 무작정 기다린다.
- 재생 중 조각을 60초 못 받으면 재생 화면 오류로 바뀌고 "돌아가기"만 있다. 같은 위치에서 다시 시도할 수 없다.
- 일부 오류는 내부 원문이 그대로 보인다: "토렌트 처리 중 오류가 발생했습니다: (예외 원문)", "플레이어를 시작하지 못했습니다: (원문)", 저장 파일 삭제의 영어 문구 "Stop playback or downloading before deleting this file", "토렌트 다운로드 실패 (HTTP 404)". 사용자에게 보일 수 있는 문구 전체는 [spec.md §12](../spec.md).
- 오류 문구 일부는 `strings.xml`이 아니라 코드에 한국어로 박혀 있어 일관된 수정이 어렵다(ViewModel·DownloadController·DownloadManager·TorrentInputResolver·TorrentRemoval·TorrentDiskStore 등).

## 2. 원하는 동작
1. **메인 오류와 다시 시도** (Q1): 실패하면 입력란에 방금 링크가 그대로 남고 오류 문구가 보인다. 다시 시도할 수 있는 오류이고 입력이 그대로면 주요 버튼 "바로 재생"이 **"다시 시도"로 바뀐다**(별도 버튼을 더하지 않는다). 누르면 같은 링크로 다시 시작한다. 입력을 고치면 버튼은 "바로 재생"으로 돌아간다. 다시 시도할 수 없는 오류(링크 형식 오류 등)는 "바로 재생" 그대로다. 오류마다 다시 시도 가능 여부는 시안 D 2절 표를 기준으로 한다.
2. **준비 화면 기다림** (Q4·Q5):
   - 정보·연결 단계에서 진행 카드에 경과 시간과 최대 대기 시간을 보인다("42초째 찾는 중 · 최대 2분"). 최대 시간은 문구에 숫자를 박지 않고 엔진의 실제 대기 한도 값에서 계산한다.
   - 피어 0명이 30초 이상 이어지면 안내 줄을 보인다: "아직 공유 중인 사용자를 찾지 못했습니다. 계속 기다리거나, 재생 목록에서 받아 두고 나중에 보세요." + 글자 버튼 "재생 목록에서 계속 받기". 하단 "재생 목록" 버튼과 같은 동작이지만 둘 다 둔다(맥락 옆 행동 안내). 피어가 1명 이상 되면 안내가 사라진다.
3. **메타데이터 실패 원인별 문구**: 네트워크가 없으면 "인터넷에 연결되어 있지 않습니다…"를, 연결은 되는데 받지 못했으면 "공유 중인 사용자를 찾지 못해…" 문구를 보인다.
4. **재생 오류** (Q6): 다시 시도할 수 있는 오류(재생 실패·재생기 시작 실패·영상 열기 실패)는 [돌아가기] [다시 시도] 두 버튼. 다시 시도는 같은 위치(±5초)에서 다시 연다. 영상 파일이 없는 오류는 다시 시도해도 같으므로 [돌아가기] 하나다.
5. **원문 숨기기**: 예외 원문·영어·경로는 사용자 문구에서 빼고 행동 문장으로 끝낸다. 문구 기준(두 문장, 60자 이내, 합쇼체, 행동으로 끝내기, 문구가 가리키는 버튼이 화면에 있어야 함)은 시안 D 1절.
6. 사용자에게 보이는 오류 문구는 모두 문자열 리소스에 등록한다.
7. 준비 중에 다운로드 작업이 사라진 경우(보통 흐름에서는 나오지 않는 방어 경로, Q7)도 "다운로드가 중지되었습니다. 다시 시도하면 이어서 받습니다." + 다시 시도 가능으로 처리한다.

## 3. 완료 조건
- 메타데이터 실패 후 메인에서 입력 없이 주요 버튼 "다시 시도" 한 번으로 같은 링크 준비가 다시 시작된다.
- 링크 형식 오류에서는 주요 버튼이 "바로 재생" 그대로다.
- 비행기 모드에서 재생을 시작하면 네트워크 문구가 보인다.
- 준비 화면에 경과 시간과 최대 대기 시간이 보이고, 최대 시간 문구는 엔진 한도 값을 바꾸면 함께 바뀐다(단위 테스트).
- 피어 0명 30초 뒤 안내 줄이 나타나고, 그 안 버튼으로 재생 목록에서 계속 받기가 된다.
- 재생 오류 화면에 "다시 시도"가 있고, 누르면 오류 직전 위치(±5초)에서 재생된다. 영상 파일 없음 오류에는 "돌아가기"만 있다.
- 사용자에게 보이는 문구에 영어 예외 메시지나 Kotlin 예외 원문이 나오지 않는다(단위 테스트로 오류 → 문구 대응표 확인, 기대값은 시안 D 2절).
- 코드 안 한국어 사용자 문구가 0개다(로그 문구 제외).

## 4. 범위 밖
- 메타데이터 대기 시간(120초)·조각 대기 시간(60초) 값 변경
- 자동 재시도(사용자가 누르지 않아도 다시 시작)
- 오류 보고 전송(서버 없음)
- 저장 공간 부족 판별 자체(→ [storage-guidance.md](storage-guidance.md)). 문구 키는 시안 D에 미리 있다.

## 5. 영향
- design: 시안 D 완료(문구 표·배치·`InlineNotice`·`Sizes.actionButtonMinWidth`). 구현 때 확인만.
- program: 마지막 입력 보존, 다시 시도 경로, 네트워크 상태 판별(`ACCESS_NETWORK_STATE` 이미 있음), 경과 시간·피어 0명 지속 시간 노출, 오류 → 문구 대응 객체(다시 시도 가능 여부·보조 동작 포함)와 테스트(M). 목록은 `design/reviews/planning-60.md` 4절.
