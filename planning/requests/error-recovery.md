# 요구사항: 실패 시 복구 흐름과 오류 문구 정리

## 1. 문제
- 토렌트 정보를 120초 동안 못 받으면 메인으로 돌아가 문구만 보인다. 링크를 다시 붙여넣어야 하는 것으로 보이고(미확인), "다시 시도" 버튼이 없다.
- 준비 화면에서 기다리는 동안 경과 시간·기대치가 본문에 없다. 피어가 0명이어도 사용자는 무작정 기다린다.
- 재생 중 조각을 60초 못 받으면 재생 화면 오류로 바뀌고 "돌아가기"만 있다. 같은 위치에서 다시 시도할 수 없다.
- 일부 오류는 내부 원문이 그대로 보인다: "토렌트 처리 중 오류가 발생했습니다: (예외 원문)", "플레이어를 시작하지 못했습니다: (원문)", 저장 파일 삭제의 영어 문구 "Stop playback or downloading before deleting this file"(미확인), "토렌트 다운로드 실패 (HTTP 404)".
- 오류 문구 일부는 `strings.xml`이 아니라 코드에 한국어로 박혀 있어 일관된 수정이 어렵다(ViewModel·DownloadManager·TorrentInputResolver).

## 2. 원하는 동작
1. **메인 오류**: 오류 문구 아래에 "다시 시도"가 있다. 누르면 방금 넣은 링크로 다시 시작한다. 입력란에도 방금 링크가 남아 있다.
2. **준비 화면 기다림**: 진행 카드에 경과 시간을 보인다("12초째 찾는 중"). 피어 0명이 30초 이상 이어지면 안내 줄을 보인다: "공유 중인 사용자를 찾지 못하고 있습니다. 계속 기다리거나, 재생 목록에서 받아 두었다가 나중에 보세요." 버튼 "재생 목록에서 계속 받기"(기존 동작).
3. **메타데이터 실패 원인별 문구**: 네트워크가 끊겼으면 "인터넷에 연결되어 있지 않습니다."를, 연결은 되는데 피어가 없었으면 지금 문구를 보인다.
4. **재생 오류**: 버튼을 "다시 시도"(기본)와 "돌아가기" 두 개로 한다. 다시 시도는 같은 위치에서 재생을 다시 연다.
5. **원문 숨기기**: 예외 원문은 사용자 문구에서 빼고 "잠시 후 다시 시도해 주세요." 같은 행동 문장으로 끝낸다. HTTP 오류는 "토렌트 파일을 받지 못했습니다(서버 응답 404). 주소를 확인해 주세요."처럼 행동을 덧붙인다.
6. 사용자에게 보이는 오류 문구는 모두 문자열 리소스에 등록한다.

## 3. 완료 조건
- 메타데이터 실패 후 메인에서 입력 없이 "다시 시도" 한 번으로 같은 링크 준비가 다시 시작된다.
- 비행기 모드에서 재생을 시작하면 네트워크 문구가 보인다.
- 재생 오류 화면에 "다시 시도"가 있고, 누르면 오류 직전 위치(±5초)에서 재생된다.
- 사용자에게 보이는 문구에 영어 예외 메시지나 Kotlin 예외 원문이 나오지 않는다(단위 테스트로 오류 → 문구 대응표 확인).
- 코드 안 한국어 사용자 문구가 0개다(로그 문구 제외).

## 4. 범위 밖
- 메타데이터 대기 시간(120초)·조각 대기 시간(60초) 값 변경
- 자동 재시도(사용자가 누르지 않아도 다시 시작)
- 오류 보고 전송(서버 없음)

## 5. 영향
- design: 문구 확정(ux-copy), 준비 화면 안내 줄·재생 오류 버튼 배치(M)
- program: 마지막 입력 보존, 다시 시도 경로, 네트워크 상태 판별(`ACCESS_NETWORK_STATE` 이미 있음), 오류 → 문구 대응 객체와 테스트(M)
- 정책: 영향 없음. 권한 추가 없음.
