# 요구사항: 출시 후 리텐션 — 평가 요청·의견 보내기·새 기능 안내

## 1. 문제
- 출시 직후 평점이 적으면 스토어 노출이 약하다. 만족한 사용자에게 평가를 부탁하는 경로가 없다.
- 불만이 있는 사용자는 스토어 1점 리뷰 말고 의견을 낼 곳이 없다.
- 업데이트로 기능이 늘어도 사용자는 알 수 없다(패치 노트가 앱 안에 없음).
- 앱에 분석 SDK가 없어 PM이 어떤 기능이 쓰이는지 알 수 없다. 지금은 Play Console 지표(설치·제거·비정상 종료·ANR·평점)만 볼 수 있다.

## 2. 원하는 동작
1. **평가 요청**: 재생을 끝까지 본 횟수가 3회가 된 뒤 재생 목록으로 돌아왔을 때, Google 인앱 리뷰 창을 한 번 띄운다. 전면 광고를 띄운 같은 순간에는 띄우지 않는다.
2. **의견 보내기**: 메인 하단(또는 도움말)에 "의견 보내기". 누르면 메일 앱이 앱 버전·Android 버전이 채워진 채로 열린다(마그넷·재생 기록은 넣지 않는다).
3. **새 기능 안내**: 업데이트 후 첫 실행에 "새로워진 점" 시트를 한 번 보인다(버전별 2~3줄, 패치 노트에서 사용자용 문장만).
4. 분석 SDK는 넣지 않는다. 지표는 Play Console을 기준으로 한다(launch가 출시 후 확인).

## 3. 완료 조건
- 조건을 만족한 사용자에게 인앱 리뷰 창이 한 번만 요청된다(Google이 실제 표시 여부를 정함).
- 의견 메일 본문에 버전 정보가 있고, 재생 목록·마그넷 정보는 없다.
- 업데이트 후 첫 실행에만 새로워진 점이 보인다.

## 4. 범위 밖
- 분석·크래시 SDK(Firebase 등) 도입: 데이터 보안 신고가 바뀌므로 별도 결정
- 푸시 알림 마케팅

## 5. 영향
- design: 새로워진 점 시트, 하단 링크 배치(S)
- program: 인앱 리뷰 라이브러리 연결, 표시 조건 순수 객체와 테스트, 버전 기록(S)
- 정책: 인앱 리뷰는 Google Play Core(Review) 라이브러리 **외부 의존성 추가**라 사용자 승인 필요. Play 정책상 리뷰를 보상과 묶거나 유도 문구를 넣으면 안 된다. 의견 메일은 사용자가 직접 보내므로 수집 아님. 데이터 보안 신고 변경 없음.
- 광고: 전면 광고와 같은 순간에 겹치지 않게 순서 규칙 필요.

## 결정 필요
- 인앱 리뷰 라이브러리 추가 승인
- 의견 받을 이메일 주소(개인정보, `launch/private/` 기준)
