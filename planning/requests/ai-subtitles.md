- 구분: **새 기능 — 검토 문서.** 구현 배정 전이며 사용자 승인이 필요하다.
- 제안: 사용자(2026-11-14 대화). 검토: PM·planning.
- 기준 코드: `main` 9d79beb. 지금 자막 기능은 토렌트 안 자막 파일(.srt·.smi·.ass)과 영상 내장 자막 트랙을 재생 화면 자막 시트에서 고르고, 설정 "자막 자동 표시"가 기기 언어 자막을 켜는 것까지다(`design/specs/subtitles.md`, `PATCH_NOTES.md`). 인터넷에서 자막을 찾거나 만드는 기능은 없다.
- 근거 표기: **[직접]** 원문 페이지를 직접 열어 확인(2026-11-14) / **[2차]** 다른 사람이 정리한 글·벤치마크 / **[미확인]** 확인하지 못함 / **[확인 필요]** 법률·정책 해석이 필요해 planning이 판단하지 않음. 출처는 문서 끝 표.

### 1-2. 보급형 기기 시장의 한계

- 2단계는 큰 음성 인식 모델을 기기 메모리에 올려 수십 분 계산한다. whisper.cpp 기준 small 약 0.85GB, medium 약 2.1GB, large 약 3.9GB 메모리가 필요하다 [직접]. RAM 4~6GB 보급형에서는 small 이상을 다른 앱과 함께 돌리기 어렵다(추정).
- 인도(Android 94.84%)·필리핀·인도네시아·베트남·브라질은 Android 비중이 크고(`marketing/market/global-torrent-markets-2026-11.md`), 보급형 기기 비중이 높을 것으로 보이나 **국가별 기기 RAM 분포 자료는 찾지 못했다 [미확인].**
- 1단계(번역)는 언어당 약 30MB 모델이라 [직접] 보급형에서도 쓸 수 있을 가능성이 높다. 실제 속도는 [미확인] → 6절 실험 E1.

## 3. 사용자 흐름 초안

화면 배치·문구는 design 몫이다. 아래는 흐름과 상태만 정한다.

### 3-1. 진입점

- **재생 화면 자막 시트**(주 진입점): 자막 묶음 맨 아래에 "AI로 자막 만들기" 한 줄. 1단계에서는 "자막 번역"(번역할 원본 자막이 있을 때만 보임), 2단계에서 "AI로 자막 만들기"(원본 자막이 없어도 보임).
- **재생 목록 카드**(보조): 완료 항목 메뉴에 같은 동작. 재생하지 않고 미리 만들어 두는 용도.
- 메인·설정에는 두지 않는다. 설정에는 "AI 자막 모델 관리"(받은 모델 크기·삭제)만 둔다.

### 3-2. 처음 쓸 때 (모델 받기 동의)

1. 무엇을 하는지: "영상의 소리를 이 기기 안에서 글로 바꿔 자막을 만듭니다. 소리와 자막은 기기 밖으로 나가지 않습니다."(2단계) / "자막을 이 기기 안에서 번역합니다. 번역은 Google 번역 기술을 씁니다."(1단계, 저작자 표시 의무 [직접])
2. 받을 크기: 번역 언어 팩 약 30MB × 필요한 언어 수(1단계), 음성 인식 모델 0.5~1.5GB(2단계, 모델 결정 후 확정).
3. 남은 저장 공간이 받을 크기 + 여유분보다 작으면 시작하지 않고 "저장 파일 관리"로 안내(기존 저장 공간 부족 문구 체계를 따름).
4. Wi-Fi가 아니면 기본으로 멈추고 묻는다. Play AI 팩은 200MB가 넘으면 Wi-Fi가 아닐 때 사용자 동의 전까지 받지 않는다 [직접] — 앱의 "Wi-Fi 전용" 설정과 같은 뜻으로 맞춘다.

### 3-3. 언어 고르기

- 번역할 언어(도착어): 기본은 기기 언어. 바꾸면 기억한다.
- 원본 언어(출발어): 1단계는 자막 파일의 언어(기존 언어 판별 결과) → 모르면 사용자가 고른다. 2단계는 자동 판별(Whisper 언어 판별) + "다른 언어면 고르기".
- 출발어 = 도착어면 번역하지 않는다(2단계에서는 "같은 언어 자막 만들기"로 동작).
- 지원하지 않는 언어 쌍이면 고르지 못하게 흐리게 보인다.

### 3-4. 진행과 취소

| 상황 | 동작 |
|---|---|
| 진행 표시 | 1단계: 자막 시트 안 줄에 "번역 중 42%". 2단계: 재생 목록 카드와 알림에 "AI 자막 만드는 중 18% · 약 25분 남음"(남은 시간은 처음 몇 분 측정 뒤 표시) |
| 재생하면서 | 1단계는 몇 초~몇 분이라 재생 중 바로. 2단계는 재생과 동시에 돌리면 끊김·발열이 커서 **기본은 재생하지 않을 때**(재생 중에 누르면 "재생을 멈추면 시작합니다 / 지금 시작" 선택) [미확인, E2로 결정] |
| 조건 | 2단계 기본값: 충전 중 + 배터리 30% 이상 + 기기 온도 정상. 조건이 깨지면 일시 정지하고 알림 "충전기를 연결하면 이어서 만듭니다". 사용자가 "지금 만들기"로 조건을 끌 수 있다 |
| 취소 | 언제든 "취소". 만든 부분까지 남길지 묻지 않고 버린다(부분 자막은 혼란) |
| 앱을 떠나도 | 2단계는 앱을 나가도 이어서 해야 하므로 포그라운드 서비스 + 알림이 필요하다(5-4) |
| 완료 | 알림 "AI 자막을 만들었습니다: 영상 제목" → 누르면 재생 목록. 재생 중이면 자막 시트에 바로 나타나고 자동 표시 규칙에 따라 켠다 |

### 3-5. 만든 자막의 표시와 관리

- 자막 시트에 "한국어 (AI 번역)" / "영어 (AI 생성)" 처럼 **태그 "AI"** 로 기존 "파일"·내장 트랙과 구분한다. 첫 표시 때 "AI가 만든 자막이라 틀릴 수 있습니다" 한 줄.
- 저장: 그 영상의 다운로드 폴더 안(재생 목록 항목·영상과 함께 지워짐). 앱 밖으로 내보내기·공유는 하지 않는다(5-3).
- 삭제: 자막 시트 행을 길게 눌러 "AI 자막 삭제", 재생 목록 "파일과 함께 삭제"·저장 파일 관리 삭제에 포함.
- 다시 만들기: 같은 언어로 다시 만들면 덮어쓴다(묻고).
- 자동 표시: "자막 자동 표시"가 켜져 있고 기기 언어 자막이 AI 자막뿐이면 AI 자막을 켠다(사람이 만든 같은 언어 자막이 있으면 그쪽 우선).

### 3-6. 실패·예외

| 상황 | 처리 |
|---|---|
| 모델 받기 실패·중단 | 오류 문구 체계(시안 D)대로 "다시 시도". 받은 만큼 이어 받기(Play 팩은 Play가 처리) |

| 소리 없음·음악만 | 결과가 거의 비면 "말소리를 찾지 못했습니다". Whisper가 음악·무음 구간에서 없는 말을 지어내는 현상이 알려져 있어 [2차, 미확인] 음성 구간 검출(VAD)로 거른다(program) |

## 5. 정책·위험

### 5-1. 모델 내려받기 방식

| 방식 | 내용 | 판단 |
|---|---|---|
| **Play for On-device AI(AI 팩)** | 앱 번들에 모델을 넣어 Play가 호스팅·전송·업데이트. 설치 시 / 설치 직후(fast-follow) / 필요할 때(on-demand). AI 팩 하나 최대 1.5GB, 앱 전체 누적 4GB, RAM·기기 모델로 타깃팅, 200MB 넘으면 Wi-Fi가 아닐 때 동의 필요. **베타**. 받은 모델은 그 앱에서만 써야 함 [직접] | **2단계 1순위.** 서버가 필요 없어 "서버 없음" 방침과 맞고, 저사양 기기에는 아예 내려주지 않을 수 있다. 베타라는 점이 위험 |
| Play Asset Delivery(일반 애셋 팩) | 팩 하나 1.5GB, install-time 누적 4GB, on-demand·fast-follow 누적 30GB [직접] | AI 팩이 안 되면 대안. 공식 안내 문서가 게임 중심으로 쓰여 있어 일반 앱 적용은 [확인 필요] |
| 직접 내려받기(우리 서버·Hugging Face 등) | 앱이 외부 주소에서 모델 파일을 받음 | **권하지 않음.** 서버 비용·운영이 생기거나, 제3자(호스팅 업체)에 사용자 IP가 전달되어 개인정보처리방침이 바뀐다 |
| ML Kit 번역 언어 팩 | Google이 필요할 때 내려받고 관리 [직접] | 1단계는 이것으로 충분 |

**실행 코드 내려받기 금지와의 관계**: Play 기기·네트워크 악용 정책은 "Google Play 밖에서 실행 코드(dex·JAR·.so 등)를 내려받는 것"을 금지한다 [직접]. 모델 가중치는 실행 코드가 아닌 데이터로 보이지만 [확인 필요], **추론 엔진의 네이티브 라이브러리(.so)는 반드시 앱(또는 Play 기능 모듈)에 넣어 배포**해야 한다. 엔진 .so를 직접 내려받는 방식은 쓰지 않는다.

### 5-2. 데이터 보안 양식·개인정보처리방침

- 소리·자막을 기기 안에서만 처리하면 개발자가 수집·공유하는 데이터는 늘지 않는다. 데이터 보안 양식 항목 변경은 없을 것으로 보이나 **ML Kit(번역 언어 팩 내려받기)이 Google에 보내는 정보(기기 정보·진단 등)를 양식에 넣어야 하는지 [확인 필요]** — launch가 ML Kit의 데이터 공개 안내로 확인한다.
- 개인정보처리방침(`launch/listing/privacy-policy-en.md`) 2절 "기기에만 저장하는 정보"에 "AI가 만든 자막과 받은 AI 모델"을, 4절 다음에 "AI 자막은 기기 안에서 처리되며 소리·자막을 보내지 않는다. 번역 언어 팩·AI 모델은 Google(Play·ML Kit)에서 내려받는다"를 더해야 한다(launch).
- 마이크 권한은 쓰지 않는다(영상 파일의 소리를 읽는 것이므로). 시스템 `SpeechRecognizer` 경로가 마이크 권한을 요구하면 그 경로는 쓰지 않는다 [미확인].
- Play AI 생성 콘텐츠 정책: 정책이 다루는 예는 챗봇·이미지 생성·실존 인물 음성/영상 생성이고, "기존 기능을 AI로 개선하는 생산성 앱"은 지금 대상이 아니라고 적혀 있다 [직접]. 자막 생성·번역은 후자에 가깝다고 보이지만 **[확인 필요]**. 대상이 된다면 앱 안 신고(부적절한 결과 신고) 기능이 필요할 수 있다.

### 5-3. 저작권 관점 [확인 필요 — 법률 판단 아님]

- 영상 대사를 글로 옮기고 다른 언어로 옮기는 것은 저작물의 복제·번역(2차적 저작물)과 맞닿는다. 이용자 기기 안에서 개인 시청 용도로만 쓰고 밖으로 내보내지 않으면 위험이 줄 것으로 보이나 나라마다 다르다 [확인 필요].
- 그래서 **만든 자막은 내보내기·공유·업로드를 하지 않는다**(4절 범위 밖에 고정). "자막 파일 저장" 같은 기능 요청이 와도 이 문서 기준으로는 하지 않는다.
- 지금도 Play 지식재산권 정책은 무단 다운로드를 부추기는 설명·스크린샷을 위반 예로 든다(`planning/market/analysis.md`). AI 자막을 홍보하면 "아무 영화나 내 언어로" 같은 메시지가 되기 쉽다. **스토어 문구에서 피할 표현**(marketing·launch 전달):
  - "자막 없는 영화도 바로 한국어로", "어떤 영화든 번역", 영화·드라마·애니 제목, 스트리밍 서비스 이름, "무료 자막"
  - 쓸 수 있는 방향: "내 영상에 자막을 만들어 접근성을 높입니다", "외국어 강의·개인 영상의 이해를 돕습니다", "기기 안에서 처리, 업로드 없음"
- 스크린샷에는 공개 라이선스 영상(Big Buck Bunny 등)과 그 영상의 자막만 쓴다.

### 5-4. 앱 용량·배터리·발열·백그라운드

- **앱 용량**: 추론 엔진 네이티브 라이브러리(ONNX Runtime 등)가 arm64 기준 수십 MB로 추정된다 [미확인]. 모든 사용자 설치 크기를 늘리지 않도록 **필요할 때 받는 기능 모듈**로 분리할 것을 권한다(program 판단). 모델은 AI 팩(on-demand).
- **배터리·발열**: 수십 분 동안 CPU/NPU를 계속 쓴다. 기본 조건을 충전 중으로 두고(3-4), 온도가 오르면 늦추거나 멈춘다. 실제 소모량은 [미확인] → E2.
- **백그라운드**: 앱을 떠나도 계속하려면 포그라운드 서비스가 필요하다. Android의 서비스 유형(예: 미디어 처리)·실행 시간 제한·Play 포그라운드 서비스 신고는 [확인 필요]. `planning/requests/background-download.md`와 구조를 함께 정한다.
- **접근성(긍정)**: 자막 없는 영상에 자막이 생겨 청각장애·난청 사용자와 소리를 끈 사용자에게 도움이 된다. 접근성 요구사항(`accessibility.md`)의 성과로 보고할 수 있다.

## 6. 성공 기준과 실험 제안 (구현 전)

실험은 program이 작은 시험 앱(본 앱과 분리, 출시하지 않음)으로 한다. 실험에 쓰는 영상은 공개 라이선스 영상·직접 녹음한 영상만 쓴다. 실험용 의존성도 본 앱에 넣기 전에 사용자 승인을 받는다.

| 실험 | 기기 | 재는 것 | 진행 기준 |
|---|---|---|---|
| **E1 번역 속도·품질(1단계)** | 최신 고성능 1대(예: 2025~2026 플래그십) + 보급형 1대(RAM 4~6GB) | 영화 1편 분량(.srt 약 1,500줄) en→ko, en→es, ja→ko(영어 경유) 번역 시간, 메모리, 언어 팩 크기. 원어민 평가: 50줄 표본에서 "뜻이 통함" 비율 | 보급형에서도 1편 **1분 이내**, "뜻이 통함" **70% 이상**(en→ko·en→es), ja→ko는 참고치 |
| **E2 음성 인식 속도·품질·발열(2단계)** | 최신 고성능 2대(Snapdragon 1, 그 밖 1) + RAM 8GB 중급 1대 | 10분 클립 3종(영어 영화 대사+음악, 한국어 드라마식 대화, 일본어 애니식 대화) × 모델 2~3종(sherpa-onnx Whisper small·medium 양자화, SenseVoice Small): RTF, 최대 메모리, 10분당 배터리 감소 %, 30분 연속 시 온도·속도 저하, 단어 오류율(표본 2분 사람 대조), 음악·무음 구간 지어내기 횟수 | 고성능 기기에서 **RTF 0.25 이하**(2시간 영화 30분 이내), **충전 없이 1시간에 배터리 20% 이하**, 메모리 부족 없음, 영어 단어 오류율 **15% 이하**, 한국어·일본어는 사람이 보고 "자막으로 쓸 만함" 판정 |
| **E3 모델 배포** | 내부 테스트 트랙 | AI 팩(on-demand) 0.5GB·1.5GB 받기 시간, Wi-Fi 동의 흐름, RAM 타깃팅으로 저사양 기기 제외 동작, 앱 업데이트 때 다시 받지 않는지 | 동의·중단·재개가 Play 기본 흐름으로 동작, 저사양 기기에 팩이 안 내려감 |

판단:

- E1 통과 → 1단계 진행 제안(사용자 승인 후 PM 배정).
- E2가 고성능 기기에서만 통과 → 2단계는 "지원 기기 한정"으로 축소 진행할지 사용자 결정.
- E2 실패(속도·발열·품질 중 하나라도) → 2단계 보류, 6개월 뒤(엔진·기기 발전) 재실험.
- E3 실패 → 2단계 보류(직접 내려받기로 바꾸지 않는다).

## 7. 기획 의견

**권고: 축소 진행.**

1. **1단계(자막 번역)는 출시 후 첫 기능 후보로 진행을 검토한다.** 위험이 낮고(언어당 30MB, 기기 안 처리, 수십 초~몇 분 [미확인]) 한국·2차 국가(스페인어·포르투갈어·인도네시아어·베트남어) 사용자에게 바로 가치가 있다. 지금 자막 기능(토렌트 안 자막 파일 받기·자동 표시) 위에 얹는 형태라 흐름이 자연스럽다.
2. **2단계(AI 자막 만들기)는 보류하고 E2·E3 실험만 먼저 한다.** 큰 모델·수십 분 작업·발열·배터리·포그라운드 서비스·대용량 배포가 한꺼번에 걸리고, 1차 출시국 다수(영어권)에서는 번역 수요가 작다. 실험이 통과하면 "고성능 기기 한정"으로 다시 제안한다.
3. **출시 전에는 넣지 않는다.** 새 외부 의존성·개인정보처리방침 변경·Play 신고 항목이 늘어나 심사 위험이 커진다.
4. 어느 단계든 **만든 자막은 기기 밖으로 내보내지 않는다**, **서버를 두지 않는다**를 고정 조건으로 둔다.

## 결정 필요 (사용자·PM)

1. 1단계(자막 번역)를 출시 후 기능 후보로 올릴지, 그 전에 E1 실험을 할지

8. 스토어·홍보 문구에서 AI 자막을 내세울지, 내세운다면 5-3의 피할 표현 기준을 marketing에 넘길지
9. 저작권·AI 생성 콘텐츠 정책 해석을 전문가에게 확인받을지 [확인 필요 항목: 5-1 모델=데이터 해석, 5-2 AI 정책 대상 여부·ML Kit 데이터 신고, 5-3 자막 생성·번역의 저작권 위험]
10. 새 용어 표 추가 요청(PM): "AI 자막"(AI subtitles), "AI 번역"(AI translation), "AI 자막 만들기"(Generate AI subtitles), 태그 "AI"
