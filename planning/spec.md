# PiecePlay 현재 동작 스펙

기준: `main` 4133a8e (v.2026.11.12.002, versionCode 27) 코드를 읽어 정리했다. §12만 `main` 1a93951 기준으로 갱신했다(이슈 #81). 루트 `SPEC.md`·`PLAN.md`는 초기 문서라 다른 곳이 많다(예: 재생기는 Media3가 아니라 LibVLC). 코드로 확인하지 못한 동작은 "미확인"으로 적는다.

## 1. 한 줄 정의

마그넷 링크 또는 `.torrent` 파일의 HTTP(S) 링크를 넣으면, 토렌트 안의 가장 큰 영상 파일 하나를 받으면서 바로 재생하는 Android 앱.

## 2. 대상 환경

| 항목 | 값 |
|---|---|
| 최소/대상 SDK | 26 / 37 |
| 권한 | `INTERNET`, `ACCESS_NETWORK_STATE`, `ACCESS_WIFI_STATE` (알림·저장소·포그라운드 서비스 권한 없음) |
| 재생기 | LibVLC (`VlcPlayerScreen`) |
| 토렌트 엔진 | libtorrent4j (세션 하나 공유) |
| 광고 | AdMob 배너·전면, Google UMP 동의 |
| 테마 | 다크 테마 하나(남색 배경, 파랑→민트). 기기 배경화면 색 미적용 |
| 언어 | 한국어만. 문구는 대부분 `res/values/strings.xml`, 일부는 Kotlin 코드에 한국어로 남아 있음(예: ViewModel·다운로드 오류, 재생 시간 표기 "현재 … / 전체 …") |
| 외부 링크 열기 | 없음. 다른 앱에서 마그넷·`.torrent` 링크를 PiecePlay로 여는 intent filter가 없어 사용자가 직접 복사·붙여넣기해야 한다 |

## 3. 입력

- 받는 값: `magnet:` 링크 또는 `http(s)://` `.torrent` 파일 주소. 길이 1~8192자.
- `http://` 주소는 자동으로 `https://`로 바꿔 받는다. HTTPS가 안 되면 "보안 연결(HTTPS)을 지원하지 않는 주소입니다…" 오류.
- `.torrent` 파일: 최대 2MiB, 요청당 10초 제한, 리디렉션 최대 5회. 첫 바이트가 bencode(`d`)가 아니면 ".torrent 파일이 아닙니다…".
- 같은 토렌트는 `MagnetIdentity.key()`(64자리 hex)로 묶인다. 같은 키면 다운로드 폴더·진행 정보·재생 목록 항목을 공유한다.
- 로컬 `.torrent` 파일 선택, QR, 검색 기능은 없다.

## 4. 재생 흐름 (상태)

`StreamUiState`: `Idle → FetchingMetadata → Buffering → Playing`, 실패 시 `Error(message)`.

1. 메인 "바로 재생" → 입력이 비면 "마그넷 또는 토렌트 파일 링크를 입력하세요."
2. 입력 해석(마그넷 그대로, `.torrent`는 내려받아 마그넷으로 변환) → 재생 목록에 추가(이미 있으면 받은 날짜 유지) → 이어볼 위치를 읽는다.
3. 다운로드 작업으로 시작한다(재생도 항상 `DownloadManager` 작업). 동시 실행 3개, 넘치면 대기열. 재생하려는 작업이 대기 중이면 다른 실행 작업 하나를 대기로 돌리고 자리를 만든다.
4. 토렌트 정보(메타데이터) 수신: 저장된 메타데이터가 있으면 그것을 쓰고, 없으면 최대 120초 기다린다. 피어 0명이 5초 이어지면 DHT·트래커 탐색을 다시 요청한다. 120초 안에 못 받으면 "토렌트 정보를 가져오지 못했습니다. 네트워크 연결과 공유 중인 사용자가 있는지 확인해 주세요."
5. 파일 선택: 토렌트 안 **가장 큰 영상 파일 하나**만 받고 나머지 파일(자막 `.srt` 포함)은 받지 않는다. 지원 확장자: mp4, mkv, avi, webm, mov, m4v, ts, flv. 없으면 "토렌트에 재생할 수 있는 영상 파일이 없습니다."
6. 버퍼링: 파일 앞 약 2초 분량 조각과 컨테이너 인덱스(mp4·mov·m4v는 `moov`)가 확보되면 `Playing`. ViewModel이 250ms마다 확인한다.
7. 재생: 완료된 파일은 파일로 직접, 미완료 파일은 `127.0.0.1` 로컬 스트림(NanoHTTPD)으로 연다. 재생 위치 앞 약 30초(조각 4~64개, 최대 64MB)를 최우선으로 받는다. 조각 하나를 60초 넘게 못 받으면 읽기가 실패한다(→ 재생 오류).
8. 재생 위치 저장: 5초마다, 앱이 백그라운드로 갈 때, 재생 화면을 닫을 때 암호화해 저장한다. 끝에서 3초 이내 위치는 다음에 처음부터 재생한다.
9. 끝까지 재생 → 위치 0으로 저장 → 재생 목록으로 이동 → 전면 광고 판단.

뒤로 가기 규칙

- 메인에서 시작한 재생을 닫으면 그 다운로드도 멈춘다. 재생 목록에서 시작했으면 다운로드는 이어 간다.
- 준비 화면의 "메인"은 어디서 시작했든 다운로드를 멈추고 메인으로, "재생 목록"은 재생만 멈추고 다운로드를 이어 가며 재생 목록으로 간다.

## 6. 재생 화면 기능

있는 것
- 재생/일시 정지, 10초 앞/뒤 버튼, 좌우 절반 두 번 탭으로 10초 이동
- 재생 막대 드래그(받은 구간·조각 맵 함께 표시), 가로 스와이프 탐색(화면 너비 = 영상 전체 길이)
- 손가락·버튼 확대(최대 8배)와 확대 상태 이동, 배율 되돌리기
- 화면 회전 버튼
- 상단: 파일 이름, 속도·받은 비율·피어 수
- 더보기 시트: 링크 추가(재생 유지한 채 다운로드 추가), 재생 위치 초기화·처음부터
- 조작 UI는 재생 중 3.5초 뒤 자동으로 숨고, 숨으면 오른쪽 아래에 시간만 남는다
- 탐색 후 기다리는 동안 "이동한 구간을 준비하고 있습니다…" 안내
- 재생 중 화면 꺼짐 방지(앱 전체에 `FLAG_KEEP_SCREEN_ON`)

없는 것
- 자막 트랙 선택, 외부 자막 파일 열기, 오디오 트랙 선택 (내장 자막을 VLC가 기본으로 보여 주는지는 미확인)
- 재생 속도, 화면 비율(맞춤/채움/늘림) 전환
- 밝기·음량 제스처, 화면 잠금, 화면 속 화면(PiP), 백그라운드 오디오
- 재생 오류 화면의 "다시 시도"(지금은 "돌아가기"만)

## 7. 재생 목록

- 재생하거나 다운로드한 링크를 최근 50개까지 암호화해 보관한다(`noBackupFilesDir/magnet_history`, 포맷 버전 -3). 50개를 넘으면 받은 날짜가 가장 오래된 항목이 목록에서 빠진다. 그 항목의 영상 파일이 함께 지워지는지는 코드상 지우지 않는 것으로 보인다(미확인, 저장 파일 관리에는 남음).
- 항목: 제목(메타데이터 받기 전에는 마그넷의 이름 또는 기본값), 상태 칩(다운로드 중/대기 중/실패/완료/미완료), 받은 양/크기·속도, 진행 막대, 이어보기 위치, 자세히 모드에서는 조각 맵·받은 날짜·마그넷 주소.
- 동작: 재생, 다운로드/중지/대기 취소, 위치 초기화, 파일과 함께 삭제(확인 창), 일괄 선택(다운로드·중지·삭제), 정렬(최근 재생순/받은 날짜순), 표시(전체/완료/미완료), 간단히/자세히, 링크 추가.
- 다운로드 중이면 2초마다 목록을 새로 읽는다.
- 검색은 없다.

## 8. 저장 파일 관리

- 받은 영상과 암호화된 진행 정보 파일을 보여 준다. 위에 개수·합계 용량, 확장자 칩(전체/.mp4/… /확장자 없음)으로 거른다.
- 한 개 또는 선택 삭제(확인 창). 실행·대기 중인 다운로드가 있으면 "파일을 삭제하려면 먼저 재생 목록의 다운로드를 중지해 주세요."
- 이 화면으로 들어가면 진행 중인 재생 스트림을 멈춘다.
- 기기 남은 용량 표시, 용량 부족 경고, 오래된 파일 추천 정리는 없다. 다운로드 시작 전 용량 확인도 없다(미확인: 용량이 차면 libtorrent 오류 문구가 그대로 보일 것으로 추정).

## 9. 다운로드

- 다운로드 작업은 ViewModel 안에서만 산다. 포그라운드 서비스·알림이 없으므로 앱을 최근 앱에서 지우거나 시스템이 프로세스를 정리하면 다운로드가 멈추고, 다시 열어도 자동으로 이어 받지 않는다(이어받기 데이터는 남아 있어 사용자가 다시 누르면 이어 받는다).
- 업로드하지 않으며, 다운로드가 끝나면 즉시 공유 목록에서 내린다(시딩 차단).
- Wi-Fi 전용·모바일 데이터 경고·속도 제한 설정은 없다. 설정 화면 자체가 없다.

## 10. 저장·개인정보

| 데이터 | 위치 | 보호 |
|---|---|---|
| 영상 파일 | `noBackupFilesDir/torrent_downloads/<key>/` | 앱 전용 저장소, 백업 제외 |
| 메타데이터·이어받기·진행 정보 | `noBackupFilesDir/torrent_state/<key>/*.bin` | Android Keystore AES-GCM |
| 재생 목록(마그넷·제목·날짜·이어보기 위치) | `noBackupFilesDir/magnet_history` | Android Keystore AES-GCM |

- 기기 밖으로 보내는 앱 자체 데이터는 없다(서버·분석 SDK 없음). AdMob·UMP SDK가 광고 ID 등을 수집한다.
- 앱 안에 개인정보처리방침·이용 안내 링크가 없다. `launch/`에도 개인정보처리방침 문서가 없다.

## 11. 광고

- 배너: 메인·재생 목록 화면 아래.
- 전면: 재생을 끝내거나 끝까지 봤을 때, 5분 이상 시청 또는 5회 완료 && 10분 쿨다운. 재생 오류로 닫을 때는 띄우지 않는다.
- UMP 동의를 매 실행 갱신하고, 동의가 필요한 지역이면 메인 아래에 "광고 개인정보 설정"을 보인다.
- 재생·준비·버퍼링·저장 파일 관리 화면에는 광고가 없다.

## 12. 오류 문구 목록 (사용자에게 보일 수 있는 것)

기준: `main` 1a93951 코드. **지금 문구**를 적는다. 바뀔 문구(새 문구·다시 시도 가능 여부·보조 동작)의 기준은 `design/specs/error-recovery.md`(시안 D) 2절이며, 요구사항은 [requests/error-recovery.md](requests/error-recovery.md)다.
"출처"가 코드 파일이면 문자열 리소스가 아니라 코드에 박힌 문구(예외 메시지)다. 이런 예외는 화면에서 `localizedMessage`로 그대로 보일 수 있다. 지금 복구 수단은 모든 항목에서 "다시 입력하거나 다시 누르기"뿐이고, 화면에 "다시 시도" 버튼은 재생 목록 읽기 실패 한 곳에만 있다.
