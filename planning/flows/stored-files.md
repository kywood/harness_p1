# 흐름: 저장 파일 관리

기준 코드: `StoredFilesScreen`, `MainViewModel.openStoredFiles/deleteStoredFile`, `TorrentDiskStore`.

## 기본 경로

1. 메인의 "저장 파일 관리" 카드 → **저장 파일 관리**. 들어갈 때 진행 중인 재생 스트림을 멈춘다.
2. 위에 "N개 · 합계 용량", 확장자 칩(전체, .mp4, .mkv, .bin, 확장자 없음 …)이 보인다.
3. 지우기
   - 한 개: 행의 삭제 → 확인 창("이 파일을 삭제할까요?" + 파일 이름) → 삭제 → 목록 새로 읽기.
   - 여러 개: 체크 또는 "전체 선택" → "선택 삭제 (N)" → 확인 창 → 일부 실패면 "N개 삭제 실패. 실패한 항목은 선택을 유지합니다."
4. "새로고침" 아이콘으로 다시 읽는다. 뒤로/닫기 → 메인.

## 제약

- 실행·대기 중인 다운로드가 하나라도 있으면 삭제를 막는다: "파일을 삭제하려면 먼저 재생 목록의 다운로드를 중지해 주세요." 사용자는 재생 목록으로 가서 중지한 뒤 다시 와야 한다(바로가기 없음).
- 파일 단위로 지우므로 영상만 지우고 진행 정보(.bin)가 남거나 그 반대가 될 수 있다. 재생 목록 항목은 그대로 남는다.
- 재생 목록의 "파일과 함께 삭제"는 영상·메타데이터·이어받기 기록·목록 항목을 한 번에 지운다. 두 화면의 삭제 단위가 다르다.

## 관찰한 불편 (요구사항으로 넘김)

- 기기에 남은 공간, 앱이 쓰는 공간이 기기 대비 얼마인지 알 수 없다. 큰 영상을 받기 전에 공간이 충분한지 알려 주지 않는다.
- `.bin` 같은 내부 파일이 사용자에게 그대로 보이고 어느 영상의 것인지 알 수 없다(파일 이름은 키 폴더 기준).
- 다운로드 중이면 삭제가 막히는데 그 자리에서 중지할 수 없다.
