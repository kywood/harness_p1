# 흐름: 링크 입력 → 준비 → 재생 → 종료

기준 코드: `MainViewModel.playFromMain/startStreaming`, `AppNavigator`, `VlcPlayerScreen`.

## 기본 경로

1. **메인**에서 링크를 입력하거나 "붙여넣기"로 클립보드 첫 항목을 넣는다.
2. "바로 재생"을 누른다.
   - 빈 입력 → 입력란 아래 "마그넷 또는 토렌트 파일 링크를 입력하세요." (화면 이동 없음)
3. **준비 화면**(단계: 정보)으로 바뀐다. `.torrent` 링크면 먼저 파일을 받아 마그넷으로 바꾼다.
4. 재생 목록에 항목이 추가된다(이미 있으면 그대로 두고 이어볼 위치를 읽는다).
5. 토렌트 정보를 받는다. 받으면 단계가 "연결", 파일 이름·피어 수·세부 정보가 채워진다. 최대 120초.
6. 가장 큰 영상 파일이 정해지면 단계가 "버퍼링", 진행률·속도가 보인다.
7. 시작 구간(약 2초 분량 + 인덱스)이 확보되면 **재생 화면**으로 바뀌고 자동 재생된다. 이어볼 위치가 있으면 그 위치로 이동한다(끝 3초 이내였으면 처음부터).
8. 재생 중: 5초마다 위치 저장, 탐색하면 그 위치 조각부터 받는다.

## 종료 경로

| 사용자 동작 | 결과 | 다운로드 | 전면 광고 |
|---|---|---|---|
| 재생 화면 뒤로/← | 메인으로 | 멈춤(메인에서 시작) | 판단함 |
| 끝까지 재생 | 재생 목록으로 | 완료됐으면 끝, 아니면 멈춤 | 판단함 |
| 재생 오류 → "돌아가기" | 메인으로 | 멈춤 | 띄우지 않음 |
| 준비 화면 "메인"/뒤로 | 메인으로 | 멈춤 | 없음 |
| 준비 화면 "재생 목록" | 재생 목록으로 | 이어 감 | 없음 |
| 앱을 백그라운드로 | 재생 일시 정지(미확인: VLC가 화면 분리 시 멈추는지), 위치 저장 | ViewModel이 살아 있는 동안 이어 감 | 없음 |
| 앱 프로세스 종료 | 다음 실행은 메인 | 멈춤, 자동 재개 없음 | 없음 |

## 실패 경로

| 시점 | 결과 화면 | 문구 | 사용자가 할 수 있는 것 |
|---|---|---|---|
| 입력 해석 실패 | 메인 | 입력 종류별 문구(spec §12) | 고쳐서 다시 |
| 메타데이터 120초 초과 | 메인 | 토렌트 정보를 가져오지 못했습니다… | 링크 다시 넣고 다시. 120초 동안 남은 시간 안내 없음 |
| 영상 파일 없음 | 메인 | 토렌트에 재생할 수 있는 영상 파일이 없습니다. | 없음 |
| 재생 중 조각 60초 미수신 | 재생 화면 오류 | 재생하지 못했습니다… | "돌아가기"만. 같은 위치에서 다시 시도 없음 |

## 관찰한 불편 (요구사항으로 넘김)

- 실패 후 메인에서 입력란이 비어 있어 다시 붙여넣어야 하는 것으로 보인다(미확인) → [requests/error-recovery.md](../requests/error-recovery.md)
- 준비 화면에서 "얼마나 더 기다려야 하는지", 피어 0명일 때 무엇을 해야 하는지 알 수 없다 → 같은 문서
- 다른 앱(브라우저·메신저)의 마그넷 링크를 눌러도 PiecePlay가 열리지 않는다 → [requests/open-links-from-other-apps.md](../requests/open-links-from-other-apps.md)
