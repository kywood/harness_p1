# 흐름: 재생 목록 이어보기

기준 코드: `MagnetHistoryScreen`, `MainViewModel.playFromPlaylist`, `PlaylistRepository`, `PlaybackResume`.

## 기본 경로

1. 메인의 "재생 목록" 카드 → **재생 목록**. 기본 정렬은 최근 재생순, 표시는 전체.
2. 이어볼 위치가 있는 항목에는 "이어보기 00:12:34"와 "위치 초기화"가 보인다.
3. 항목의 "재생"을 누른다 → 준비 화면 → 재생 화면.
   - 이미 받은 파일(완료)은 파일로 바로 열고, 미완료면 로컬 스트림으로 연다.
   - 길이를 알게 되고 탐색 가능해지면 저장 위치로 이동한다. 이동했다는 안내(토스트 등)는 없다.
4. 재생을 닫거나 뒤로 → 재생 목록으로 돌아온다. 다운로드는 이어 간다(재생 목록에서 시작했으므로).
5. 끝까지 보면 위치가 0이 되고 재생 목록으로 돌아온다.

## 위치 다루기

- 처음부터 보기: 목록의 "위치 초기화" 또는 재생 중 더보기 → "재생 위치 초기화 · 처음부터".
- 저장 시점: 5초마다, 앱이 백그라운드로 갈 때, 재생 화면을 닫을 때. 탐색 중·버퍼링 대기 중에는 저장하지 않는다.
- 끝 3초 이내 위치는 다음 재생 때 처음부터.

## 다운로드만 하기

- 재생 목록의 "링크 추가" → 대화상자에 링크 → "다운로드": 재생 없이 작업으로 추가(동시 3개, 넘치면 "다운로드 대기 중").
- 항목별 다운로드/중지/대기 취소, 선택 항목 일괄 다운로드·중지·삭제.
- 재생 화면 더보기 → "링크 추가"도 같은 대화상자다.

## 관찰한 불편 (요구사항으로 넘김)

- 이어보기는 재생 목록 안에서만 보인다. 메인에서 "최근 보던 영상 이어보기"로 바로 갈 수 없다 → [requests/resume-continue-watching.md](../requests/resume-continue-watching.md)
- 이어볼지 처음부터 볼지 재생 시작 때 고를 수 없고, 이동했다는 안내도 없다 → 같은 문서
- 목록이 50개로 잘리는데 사용자는 "최근 50개" 문구 말고는 알 수 없고, 빠진 항목의 파일은 저장 파일 관리에만 남는 것으로 보인다 → [requests/storage-guidance.md](../requests/storage-guidance.md)
- 항목이 많아지면 찾을 방법이 정렬뿐이다(검색 없음) → [requests/playlist-search.md](../requests/playlist-search.md)
