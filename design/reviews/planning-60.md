## 1. 세 질문의 결론

### (a) 메인 하단이 붐빈다 → 설정 화면을 먼저 만들지 않는다. 메인 하단은 "법적으로 꼭 있어야 하는 것"만, 나머지는 이용 안내 시트로 모은다

결론:

1. **출시 전에는 설정 화면을 만들지 않는다.** 설정 화면은 모바일 데이터 안내(5, 새 기능)와 함께 생기는 것이고, 켜고 끌 항목이 하나도 없는 설정 화면은 빈 껍데기다. 법적 진입점 때문에 화면 하나와 내비게이션(`AppScreen`)을 먼저 늘릴 이유가 없다.
2. **메인 하단에는 아래만 둔다(최대 4개 링크 + 안내 한 줄 + 버전).** 시안: [`design/specs/main-legal-footer.md`](../specs/main-legal-footer.md)
   - 저작권 안내 한 줄
   - 링크: 이용 안내 · 개인정보처리방침 · 오픈소스 라이선스 · (동의 필요 지역) 광고 개인정보 설정
   - 버전
3. **도움말·의견 보내기·새로워진 점은 메인 하단에 따로 두지 않고 "이용 안내" 시트 안에 넣는다.** 첫 사용 안내(4)의 "도움말(물음표)" 진입점도 별도 아이콘 대신 이용 안내 시트 맨 위 "사용 방법 다시 보기"로 대체할 것을 제안한다(→ 되묻기 Q9).
4. **설정 화면이 생기는 시점(5가 승인되는 시점)의 규칙**: 메인 오른쪽 위에 톱니 아이콘 하나를 두고, 설정 화면 맨 아래 "정보" 묶음에 버전·오픈소스 라이선스·광고 개인정보 설정·(광고 제거)를 옮긴다. 메인 하단에는 저작권 안내 한 줄 · 이용 안내 · 개인정보처리방침만 남긴다. 개인정보처리방침은 "메인에서 두 번 이하 탭" 조건이 있으므로 설정 안으로만 숨기지 않는다.
5. **배너 광고와의 간격**: 하단 링크가 배너 바로 위에 붙으면 잘못 누르기(AdMob 정책상 "실수로 인한 클릭 유도")가 생긴다. 하단 링크 묶음과 배너 사이에 `Spacing.xl`(24dp) 이상을 둔다. 시안 A에 넣었다.

### (b) 재생 화면 상단 버튼 → 오른쪽 아이콘은 세로 화면 기준 최대 4개, 배율 3버튼은 접는다

지금 상단: ← · 제목/통계 · 회전 · 축소 · 배율(1.0×) · 확대 · 더보기 — 오른쪽만 5개(240dp). 360dp 세로 화면에서 제목이 이미 좁다.

결론(자막·TV·잠금이 실제로 승인될 때 적용, 지금은 규칙만 정한다):

| 위치 | 둔다 | 이유 |
|---|---|---|
| 상단 오른쪽(최대 4개, 순서 고정) | TV로 보내기(기기가 있을 때만) · 자막 · 회전 · 더보기 | TV 아이콘은 Google Cast 디자인 체크리스트상 상단 바에 두어야 한다. 자막은 영상 중 자주 바꾼다 |
| 상단, 통계 칩 옆 작은 칩 | 배율(1.0×가 아닐 때만, 누르면 1.0×), 재생 속도(1.0×가 아닐 때만) | 기본값일 때는 보이지 않게 해 자리를 비운다 |
| 더보기 시트 | 확대·축소(− 배율 +를 한 줄로), 재생 속도, 화면 비율, 오디오 트랙(자막 시트에 같이 넣지 않을 경우), 링크 추가, 처음부터 | 두 손가락 확대가 이미 있어 확대 버튼은 보조 수단이다 |
| 화면 왼쪽 가운데(상단 바 밖) | 잠금 | 다른 동영상 앱과 같은 위치. 상단 바를 비우고, 잠금 해제 버튼도 같은 자리에 띄운다 |

- 지금 당장 바꿀 것은 없다(#48 배치 유지). 자막(6)이 승인되면 그때 배율 3버튼을 더보기 시트로 옮기는 작업을 같이 한다.
- 화면 테스트가 `cd_zoom_in`/`cd_zoom_out` 설명으로 버튼을 찾으면 그때 program과 같이 고친다.

### (c) 오류 문구 기준

[`design/specs/error-recovery.md`](../specs/error-recovery.md) 1절에 전체 기준과 문구 표를 넣었다. 요약:

1. **두 문장**: ① 무슨 일이 있었는지 ② 사용자가 할 일. 두 번째 문장은 동사로 끝낸다("…해 주세요", "…하세요"). 원인 설명이 꼭 필요하면 ①에 붙인다("…를 찾지 못해 …하지 못했습니다").
2. **길이**: 한 문구 60자 이내(공백 포함), 목표 45자. 메인 입력란 아래(360dp에서 약 25자/줄)에서 3줄을 넘지 않게 한다.
3. **말투**: 합쇼체("~습니다", "~해 주세요"). 사과("죄송합니다"), 느낌표, 사용자 탓("잘못 입력하셨습니다")을 쓰지 않는다.
4. **원문 금지**: 예외 메시지, 영어, 클래스 이름, 경로를 넣지 않는다. 숫자는 행동에 도움이 될 때만(HTTP 상태 번호는 괄호 안 "서버 응답 404").
5. **용어**: 문장 안에서는 "공유 중인 사용자", 칩·수치에서는 "피어 N명"(자리 때문). "토렌트 정보"(메타데이터), "링크"(마그넷·주소 모두), "받다"(다운로드 동사)로 통일한다.
6. **문구와 버튼이 맞아야 한다**: 문구가 "다시 시도해 주세요"로 끝나면 화면에 "다시 시도"가 있어야 한다. 버튼이 없으면 다른 행동 문장으로 끝낸다.

## 4. 구현에 필요한 것 (program 요청 후보)

design 범위 밖이라 고치지 않고 적는다. PM이 구현 배정 때 program에 넘긴다.

1. 오류 → 문구 대응 객체(예: `FailureCopy`): 오류 종류마다 문자열 키, 다시 시도 가능 여부, 보조 동작(저장 파일 관리 등)을 돌려준다. 단위 테스트로 원문이 섞이지 않음을 확인(시안 D 2절 표가 기대값).
2. 마지막 입력 보존과 메인 다시 시도 경로, 네트워크 연결 판별.
3. 준비 화면에 경과 시간(초)과 피어 0명 지속 시간을 노출(지금은 `MetadataMonitor`의 한국어 원문 안에만 있다).
4. 재생 오류 "다시 시도" 콜백(같은 위치 ±5초).
5. 메인 컴포저블에 새 콜백 3개(이용 안내 열기는 화면 안 상태로 가능, 개인정보처리방침 브라우저 열기, 오픈소스 라이선스 화면 이동) — 콜백 시그니처 변경.
6. `AppScreen`에 오픈소스 라이선스 화면 추가, 라이선스 전문 텍스트(`res/raw/`)를 실제 배포 산출물의 LICENSE 파일에서 복사.
7. 코드 안 사용자 문구(ViewModel·DownloadController·DownloadManager·TorrentInputResolver·TorrentRemoval·TorrentDiskStore 등)를 문자열 리소스로.

## 5. 확인하지 못한 것

- 에뮬레이터 확인 없음(이번은 문서 시안만, 코드 변경 없음). 시안의 줄 수·잘림은 360dp·글자 100% 기준 추정이다.
- 라이트 테마는 없다(다크 하나, `renewal-plan.md` 1절). 라이트·다크 확인 항목은 해당 없음.
- 개인정보처리방침 URL, 라이선스 버전·고지 내용(특히 `libvlc-all`에 포함된 서드파티 모듈 목록과 libtorrent4j의 OpenSSL 포함 여부)은 산출물에서 확인하지 않았다.
