# 시안: 받는 순서 선택

- 이슈: #178
- 배경: `program/investigations/playback-start-2026-11.md`(받기 전용 작업을 앞에서부터 받게 바꾼 이유, 개선안 A)
- PM 결정(2026-11-14, 사용자 제안·승인): 받기 전용 작업의 받는 순서를 사용자가 고른다. 앱 전체 기본값은 설정에, 영상별 덮어쓰기는 재생 목록 카드에 둔다. 재생 중에는 어느 쪽이든 보는 위치부터 받는다(변경 없음)
- 상태: 구현과 함께 쓴 시안(program 작성). 화면 확인(에뮬레이터 캡처)은 하지 못했다 — 7절

## 1. 설정 화면: 다운로드 묶음

`settings-wifi.md` 2절의 "다운로드" 묶음에서 Wi-Fi 전용(과 그 안내 줄) 아래에 항목 하나를 더한다.

```
│ 다운로드                                             │
│ Wi-Fi 전용                                  [  ●]   │
│ 모바일 데이터에서는 다운로드를 멈춥니다.               │
│ (안내 줄: 켬 + 모바일 데이터일 때만)                   │
│ 받는 순서                      앞부분부터        ›   │  SettingsLinkItem(value, onClick)
```

| 요소 | 컴포넌트·토큰 |
|---|---|
| 항목 줄 | 기존 `SettingsLinkItem(title, value, onClick)` 그대로. 제목 `bodyLarge` `onSurface`, 지금 값 `bodyMedium` `onSurfaceVariant`, 끝 화살표. 컴포넌트는 바꾸지 않았다 |
| 지금 값 | 저장된 값의 항목 이름("앞부분부터" / "빠르게 받기") |
| 누르면 | 2절 선택 창(두 항목) |
| 저장 | 고르면 창이 내려가고, 저장에 성공한 뒤 줄의 값이 바뀐다. 실패하면 값은 그대로이고 기존 스낵바 `settings_save_failed` |

## 2. 선택 창

설정 화면과 재생 목록 카드가 같은 창(`DownloadOrderSheet`)을 쓴다. 항목 수만 다르다.

```
┌ AppBottomSheet: 받는 순서 ─────────────────────────┐
│ ( ) 기본 설정 따름                    [앞부분부터]   │  영상별 선택에만. 태그 = 지금 기본값
│ (●) 앞부분부터                                      │
│     받는 중에도 바로 재생하기 쉽습니다.               │
│ ( ) 빠르게 받기                                     │
│     전체를 더 빨리 받습니다. 다 받은 뒤에 보기 좋습니다. │
└─────────────────────────────────────────────────────┘
```

| 요소 | 컴포넌트·토큰 |
|---|---|
| 창 | 기존 `AppBottomSheet(title = "받는 순서", skipPartiallyExpanded = true)` |
| 항목 | 기존 `RadioListItem`, 묶음은 `Modifier.selectableGroup()` |
| 설명 줄 | `RadioListItem`에 `supporting: String?` 인자를 더했다(M3 `ListItem.supportingContent`, `bodyMedium` `onSurfaceVariant`). 기존 호출에는 영향 없음 |
| "기본 설정 따름" 태그 | 기존 `tag` 인자에 지금 앱 기본값의 이름을 넣는다. "기본 설정"이 지금 무엇인지 창을 닫지 않고 알 수 있게 |
| 항목 순서 | 설정: 앞부분부터(기본값) → 빠르게 받기. 영상별: 기본 설정 따름(기본) → 앞부분부터 → 빠르게 받기 |
| 동작 | 항목을 누르면 바로 고르고 창이 내려간다(확인 버튼 없음, 자막 시트와 같은 방식) |

## 3. 재생 목록 카드

### 진입점 결정

카드에는 더보기 메뉴가 없다. 맨 아래 동작 줄은 `[재생] [다운로드 동작] ... [삭제]`로 이미 차 있다.

- 360dp 화면에서 카드 안쪽 폭은 약 296dp(화면 여백 16dp × 2, 카드 안 여백 16dp × 2)다.
- 동작 줄에서 재생 버튼(약 96dp)과 삭제(48dp), 간격(8dp × 2)을 빼면 글자 버튼 자리는 약 136dp다.
- 영어에서 "Cancel queue"(아이콘 포함 약 130dp)와 "Download order"(약 135dp)를 나란히 둘 수 없다. 지금도 다운로드 동작 글자는 두 줄 줄바꿈을 허용해 겨우 맞춘 줄이다(#161).

그래서 **동작 줄에 넣지 않고, 이어보기 줄과 같은 모양의 줄을 동작 줄 바로 위에 따로 둔다.** 왼쪽에 영상별 값 표시, 오른쪽에 글자 버튼을 두어 "표시"와 "진입점"을 한 줄로 묶는다.

```
┌ 재생 목록 카드 ───────────────────────────────────┐
│ Big.Buck.Bunny.2008.1080p.mkv                [☐]  │
│ [● 다운로드 중]  1.2 GB / 3.4 GB · 2.1 MB/s       │
│ ▓▓▓▓▓▓░░░░░░░░░░                                  │
│ (자세히: 조각 맵, 받은 날짜, 주소)                   │
│ 이어보기 12:34                       위치 초기화    │  (있을 때만)
│ [● 빠르게 받기]                         받는 순서   │  ← 새 줄
│ [▶ 재생] [■ 중지]                          [🗑]    │
└───────────────────────────────────────────────────┘
```

| 요소 | 컴포넌트·토큰 |
|---|---|
| 줄 | `Row(fillMaxWidth, CenterVertically)`. 왼쪽 `Box(weight 1f)`, 오른쪽 글자 버튼. 이어보기 줄과 같은 구조 |
| 글자 버튼 | 기존 `TextAction("받는 순서", tone = MUTED)`. 터치 높이 48dp(`TextAction` 기본). 일괄 작업 중에는 다른 동작과 같이 비활성 |
| 영상별 값 표시 | 기존 `StatusChip(이름, StatusTone.NEUTRAL)`: "빠르게 받기" 또는 "앞부분부터". "기본 설정 따름"이면 표시 없음(왼쪽이 빈다) |
| 다 받은 영상 | 줄 전체를 숨긴다(버튼도 표시도 없음). 받을 것이 없어 값이 뜻이 없다 |
| 누르면 | 2절 선택 창(세 항목). 지금 값이 골라져 있다 |
| 저장 | 저장에 성공하면 목록을 다시 읽어 표시가 바뀐다. 실패하면 값은 그대로이고 목록 위 오류 줄에 `settings_save_failed` |
| 간단히 보기 | 줄을 그대로 보인다(동작이므로 숨기지 않는다) |

360dp에서 한 줄 폭: 칩 "From the start"(약 125dp) + 버튼 "Download order"(약 135dp) = 약 260dp < 296dp. 칩 글자는 한 줄이고, 글자 크기를 키워 폭이 모자라면 칩이 줄어든다(버튼이 먼저 자리를 잡는다).

## 4. 적용 규칙 (program)

| 상황 | 동작 |
|---|---|
| 순서 결정 | `영상별 값 ?: 설정 기본값`(`DownloadOrderPreference.effective`) |
| 앞부분부터 | 받기 전용 작업이 파일 앞에서부터 받는다(libtorrent sequential 켬) |
| 빠르게 받기 | 받기 전용 작업이 받을 수 있는 조각부터 받는다(sequential 끔). 첫·끝 조각 우선(인덱스 미리 받기)은 그대로 |
| 받는 중에 바꿈 | 바로 적용 |
| 재생 중에 바꿈 | 재생 중에는 보는 위치부터 받는다. 재생이 끝나 받기 전용으로 돌아갈 때 새 값이 적용된다 |
| 설정 기본값을 바꿈 | 영상별 값을 정하지 않은 진행 중 작업에도 바로 적용 |
| 저장 | 설정: `AppSettings` 포맷 3. 영상별: `MagnetHistory` 포맷 -4. 이전 포맷은 그대로 읽는다 |

## 5. 최종 문구 (strings.xml)

| 키 | 한국어 | 영어 |
|---|---|---|
| `download_order_title` | 받는 순서 | Download order |
| `download_order_use_default` | 기본 설정 따름 | Use default setting |
| `download_order_from_start` | 앞부분부터 | From the start |
| `download_order_from_start_desc` | 받는 중에도 바로 재생하기 쉽습니다. | Easier to play while it's still downloading. |
| `download_order_fastest` | 빠르게 받기 | Fastest |
| `download_order_fastest_desc` | 전체를 더 빨리 받습니다. 다 받은 뒤에 보기 좋습니다. | Finishes the whole download sooner. Best for watching after it's done. |

- 설정 항목 제목, 선택 창 제목, 카드의 글자 버튼이 모두 `download_order_title`을 쓴다(같은 뜻은 같은 키).
- 저장 실패는 새 문구를 만들지 않고 기존 `settings_save_failed`("설정을 저장하지 못했습니다. 다시 눌러 주세요.")를 쓴다.

## 6. 접근성

- 설정 항목 줄은 `SettingsLinkItem`이 한 줄로 합쳐 읽는다: "받는 순서, 앞부분부터, 버튼".
- 선택 창 항목은 라디오 버튼 역할이고, 이름 → 설명 순서로 읽는다. "기본 설정 따름"은 태그(지금 기본값)를 이어 읽는다.
- 카드의 칩은 값 이름만 읽는다("빠르게 받기"). 바로 옆에 "받는 순서" 버튼이 있어 뜻이 이어진다.
- 터치 영역: 설정 줄 56dp 이상, 선택 창 항목은 `ListItem` 두 줄 높이, 카드 글자 버튼 48dp.

## 7. 확인하지 못한 것 / design 확인 필요

- 에뮬레이터·실기기 화면을 보지 못했다(이 작업 중 에뮬레이터 사용 금지). 360dp 폭 계산은 글자 수 기준 추정이다. 확인할 것: 카드 새 줄의 영어 폭, 글자 크기 130%, 가로 화면, TalkBack 읽기 순서.
- 카드마다 줄이 하나 늘어 덜 받은 항목의 카드 높이가 약 48dp 커진다. 높이가 부담이면 카드에 더보기 메뉴를 만들어 "받는 순서"와 "위치 초기화"를 함께 옮기는 안을 design이 검토한다.
- 칩에 `StatusTone.NEUTRAL`(회색 점)을 썼다. 상태 칩과 구분되는 모양(아이콘, 보조 글자)이 필요하면 design이 정한다.
- 저장 실패 문구를 `settings_save_failed`로 같이 쓰는 것이 카드에서도 자연스러운지.
